## 1. 判据（每个形状：按什么判 / 为什么 / 已知会漏什么）

### 形状 A：护栏查在读之前

**按什么判**（三步，全是 AST 上的真数据流，不靠名字猜）：

1. **状态元**（state cell）：两种。
   - 模块级变量：模块顶层赋值的名字（如 `_io._QUARANTINED`）。
   - 类属性：`self.X`（按类收敛）。
2. **每个函数算读写摘要**：
   - 读：函数体里引用过该状态元（`is_quarantined` 的函数体里有 `_QUARANTINED` ⇒ 它**读**这个元）。
   - 写：函数体（含它调用到的同仓函数，跨模块走 import 解析，传递闭包）里对该状态元
     有赋值 / `.add()` / `.update()` 等变更。
   - 写分两档：**无条件写**（存在一条全无条件调用路径能写到它）和**仅失败路径写**
     （所有写路径都要经过 `except` 块、或"判坏→return None"那样的失败分支）。
     分档是刻意为之：懒加载模式（`if not inited: load()` 里面无条件置 `inited=True`）
     是**合法**的，不能报；只有"写只发生在失败路径"的才是形状 A 的语义。
3. **命中条件**（全部满足才报）：
   - 函数 F 里有个守卫 `if <test>: return/raise`，`test` 读到状态元 S（直接引用，
     或调用一个**直接**读 S 的判定函数，如 `is_quarantined(p)`）；
   - 守卫**之后**（源码顺序）F 里有一个调用，其摘要对 S 是**仅失败路径写**
     （如 `load_json_or_quarantine(p)` —— 它内部在 except / 类型不对分支里 `_QUARANTINED.add`）；
   - F 在那次读之后还有**写盘动作**（调用名含 write/save/dump/replace… 或 `write_text` 等）。
     —— "读改写函数"本来就是形状定义的一半，这一条把判定钉在形状上。

**为什么这么定**：病灶的本质是"守卫的真值要等人读过才存在，而第一次触碰恰恰是写侧自己那次读"。
静态上等价于：**守卫读的状态，被它后面那次调用在失败路径上写**。用真数据流（谁的读、谁的写、
在哪条路径上）而不是字符串相似，是为了让判据可审：报出来的每一条都能指着"这个守卫读 S、
这个调用写 S、写只在失败分支"三件事。

**已知会漏**（结构上做不到，不是调参问题）：
- 判定和读分居**两个函数**、中间隔着回调/多态（如守卫在 A 函数、读在传进来的 loader 里）——
  调用图解不出来就不报。
- 状态不走变量/属性（比如直接问文件系统 `if p.exists() ... is_quarantined` 之外的另一种
  "问盘上有没有"的判定），本文只认"内存状态元"这一种载体。
- 守卫和读在不同**文件**但同进程时序上仍是先判后读（跨模块 import 能解一层；
  经字符串反射 / 动态 import 的解不了）。

### 形状 B：同一个判据在多处，已经不一致

拆成四个子判据（每个成绩单对号入座，判据各自独立可审）：

**B1 · 名单族分歧**（成绩单④前半：两张敏感文件黑名单）
- 按什么判：模块/类级的**字符串集合字面量**（≥3 项），变量名像 deny-list
  （`blocked / sensitive / blacklist / deny / forbidden / secret / banned / disallow`）；
  两个这样的集合在**归一化**后共享 ≥2 个条目就算"同一族"
  （归一化：小写、剥 `*.` / 前导 `.` —— 让 `*.key` 和 `.key` 认识彼此）。
  同族即互相对差异：报"这个集合缺这些条目，那些在族里别处有"。
- 为什么：两张名单只要共享条目就说明管的是同一类事；条目差集就是"一处加了一项、另一处没跟"。
- 已知会漏：名字不像 deny-list 的名单（判据含名字项，是刻意的保守）；条目经过运算拼出来的名单；
  共享条目 <2 的两张真名单。

**B2a · 死词**（成绩单③：写侧换了现役词，消费侧还在等旧词）
- 按什么判：一个字符串字面量 L 在**非测试**代码里只出现在**匹配位**
  （`== / != / in / not in`、`startswith / endswith` 的实参），在任何**取值位**
  （赋值、实参、返回、字典键值、f-string 静态段……）都不出现 ⇒ L 没有生产者。
  再要求一个**同族见证**：存在某个有生产者的字面量 P，与 L 共享一个 ≥4 字符的 token
  （按 `_` 切），或两者比较的是同一个变量名/字段名 ⇒ 说明"这附近有个现役词，而 L 不是它"。
  两个条件同时满足才报。
- 为什么：`escalation_exhausted` 全仓没有生产者（只在注释/docstring/测试里），
  而同通道的现役词 `no_escalation_path` 有。单报"查了没人产的字面量"会把
  `"__main__"` 这类运行时产的全咬上来，所以必须带同族见证。
- 已知会漏：写侧和消费侧用完全不同措辞的词（无共享 token，认不出是同族）；
  词经字符串拼接/常量折叠产生。

**B2b · 窄前缀判据**（成绩单②：`cancelled_by_user` 漏了同族 `cancelled_during_pause`）
- 按什么判：`startswith(L)` / `endswith(L)` / `in` 匹配位上的字面量 L，
  而 L 自己有生产者；同时存在另一个有生产者的字面量 P，与 L 首个 token 相同（按 `_` 切，≥4 字符）
  —— 但按该匹配位的语义 P **不**被 L 覆盖（`startswith` 位：P 不以 L 开头；`in` 位：L 不是 P 的子串）
  ⇒ 报"P 也会出现，这个判据接不住它"。
- 为什么：`cancelled_by_user` 有生产者、是真词，坏在**判得窄**；与 B2a（词死了）正好互补。
- 已知会漏：同族词无共享首 token（如 `user_cancel` vs `cancelled_by_user`）；
  判据用正则/多条件组合绕开单字面量的。

**B3 · 同一件事写了两遍、只改了一遍**（成绩单④后半：命令包装两份，一份传 `env=` 一份不传）
- 按什么判：**同一个文件**里两个函数（一个方法、一个模块级也算），体都调
  `subprocess.*`（run/Popen/check_output），归一化 token 袋（调用点名、常量、kwargs 名；
  `self.` 归一掉）的 Jaccard 相似度 ≥ 阈值 ⇒ 判为"同一件事的两份实现"，
  然后把两份在**危险 sink 实参上的差**列出来（这份传了 `env=`、那份没传；shell=True vs False…）。
- 为什么：阈值兜"是不是复制出来的两份"，sink 实参差集兜"改的时候只改了一遍"。
- 已知会漏：跨文件的重复（v1 只看同文件，见报告 §4）；相似度掉到阈值下的；
  sink 不是 subprocess 的两份重复。

**B4 · 同一资源的成组管理函数，存储面不一致**（成绩单⑤：`mcp_server_delete` 只删配置、不动注册表）
- 按什么判：同文件里，调过**同一个资源读取器**（如都调 `load_mcp_configs`）的函数算一组。
  组内若有兄弟在"读取器之外"还触达了**单例存储**（调 `get_*` 型访问器、并在拿到的对象上
  调方法 / 改属性），而 F 对那个单例**一次都没碰**、且 F 自己对该资源有**写动作**
  （调 `save_*`）⇒ 报"F 管这个资源但只动了配置面，注册表面归兄弟管"。
- 为什么：add/delete/reconnect/refresh 都管 MCP 服务器这一份资源（都 `load_mcp_configs`），
  reconnect/refresh 喂 `get_registry()`、add/delete 不喂 —— 这个差集就是"一处动了、一处没动"。
- 已知会漏：资源读取器名字不统一（一组函数各用各的 loader）；组内只有两个函数、
  且谁都没碰第二存储面（此时静态看不出"该碰"）；跨文件的管理组。
