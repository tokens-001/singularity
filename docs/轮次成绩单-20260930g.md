## 一、怎么设计的，以及**设计上就有的两个缺口**

照抄 `round-20260930`（基线差分验证轮）的配方：**小项目 + 基线里 commit 一个必失败的测试**。

- 题目：两个模块 `greeter.py` / `fare.py`，各自要有独立的 pytest 测试文件
- 项目仓手工种坏测试：`tests/test_qq7.py::test_qq7`（`assert 1 == 2`，commit `efd9707`）
- 项目仓是**先 `ensure_repo()` 建好、种完、再起跑**的（`ensure_repo` 幂等，系统会复用）

### 🔴 缺口①：这轮**考不到 `ae75def0` 的加严那半**

架构师把「实现」和「测试」**拆成了不同任务**，于是**每个任务只声明 1 个产出文件**：

```
T1 → ['greeter.py']   T3 → ['tests/test_greeter.py']   T6 → []（[只读]）
```

**声明只有 1 个文件时，「缺任何一个」≡「一个都没交」** ⇒ 新旧判据**完全等价**，没有判别力。
（f 轮之所以能考出来，是因为它的架构给了 `['src/parser.py', 'tests/test_parser.py']` 这种双文件声明。）

⇒ **下一轮要考这半，得在 `constraints` 里写死「实现和测试必须由同一个任务交付」。**
⚠️ 而且那也**不保证**架构师照做 —— 这是"逼出来的条件"，报告里要标明。

### 🔴 缺口②：`347c3ee2` 撞不上

T1~T4 都是**单文件、diff < 50 行** ⇒ `_is_trivial_change` 判真 ⇒ **多模型审查整段跳过**
（`e538c0d3` 之后是"测试照跑、只跳多模型审查"）。所以那条判据这轮结构上没有触发机会。
