## 🔴 已核实的安全口子（不来自 ZCode，是我顺着评审的话读出来的）

`src/singularity/scheduler/executors/openai_agent.py:662-669`

```python
def _check_permission(self, tool_name: str, args: dict) -> tuple[bool, str]:
    """Permission 检查。如注入 checker 则调用，否则默认允许。"""
    if self._permission_checker:
        try:
            return self._permission_checker(...)
        except Exception:
            pass                      # ← ① 吞掉
    return True, ""                   # ← ② 默认放行
```

**同一个函数里叠了两个 fail-open**：
1. `_make_permission_checker()`（`_dispatch_skills.py:176`）自己坏了会 `return None`
   ⇒ `if self._permission_checker:` 为假 ⇒ **直接 `return True`**。
2. 就算 checker 在，**它一旦抛异常**（`request_approval` 超时/IO 挂等）⇒ `except: pass`
   ⇒ **还是 `return True`**。

⇒ **权限检查这条链上任何一环坏掉，工具就静默获得全部放行。**
作者注释写的是"如注入 checker 则调用，否则默认允许"——**"默认允许"是 fail-open**，
而这里正是 §25「门禁类必须 fail-closed」该管的地方。

**与 ZCode 挖出的另两条是同一方向**（`router.py:159` / `_observer_tools.py:135`）：都是"挂了就往宽松走"。
