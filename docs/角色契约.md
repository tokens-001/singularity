# 角色输入输出契约

> 来自 `专家团队架构.md`。每个角色固定 schema。上游不按 schema 出，下游拒绝接收。
> 日常不加载，实现角色时才用。

## ① 产品经理
```
输入：用户自然语言描述
输出：{
  "goal": "产品要解决什么问题",
  "scope": "做什么和不做什么",
  "features": [{"name": "...", "priority": "P0/P1/P2", "description": "..."}],
  "success_criteria": ["可验证的成功标准"],
  "constraints": ["已知约束"],
  "competitors": [{"name": "...", "strength": "...", "weakness": "..."}]
}
边界：不给技术方案，不做架构判断
```

## ② 交互设计师
```
输入：PRD
输出：{
  "user_flows": [{"name": "...", "steps": ["..."]}],
  "page_tree": [{"page": "...", "children": [...]}],
  "key_interactions": [{"trigger": "...", "feedback": "...", "edge_cases": ["..."]}],
  "state_machine": {"states": [...], "transitions": [...]}
}
边界：不设计视觉，不画具体 UI
```

## ③ UI 设计师
```
输入：PRD + 交互方案
输出：{
  "color_system": {"primary": "#...", "surface": "#...", ...},
  "typography": {"heading": "...", "body": "...", "scale": [...]},
  "spacing": {"unit": 4, "scale": [...]},
  "component_style": [{"name": "...", "appearance": "...", "states": [...]}],
  "responsive_breakpoints": {"mobile": 375, "tablet": 768, "desktop": 1280}
}
边界：不写代码，不定义组件实现细节
```

## ④ 研究员
```
输入：PRD（拿到后即可启动，与交互/UI设计并行）
输出：{
  "market_findings": [{"source": "...", "finding": "..."}],
  "tech_options": [{"name": "...", "pros": [...], "cons": [...], "fit": "high/medium/low"}],
  "risk_areas": [{"area": "...", "risk": "...", "mitigation": "..."}],
  "recommendation": "一句话建议"
}
边界：只调研不决策，决策权归产品经理
```

## ⑤ 系统架构师
```
输入：PRD + 交互/UI方案 + 调研报告
输出：{
  "modules": [{"name": "...", "responsibility": "...", "depends_on": [...]}],
  "data_model": {"entities": [...], "relationships": [...]},
  "api_contracts": [{"method": "GET/POST/...", "path": "...", "input": {...}, "output": {...}}],
  "tech_stack": {"language": "...", "framework": "...", "database": "...", "cache": "...", "mq": "..."},
  "constraints": [{"type": "security/performance/reliability", "rule": "...", "check": "如何验证"}],
  "tasks": [{"id": "...", "title": "...", "description": "...", "complexity": "low/medium/high",
             "phase": "frontend/backend/data/devops", "depends_on": ["task_id"], "acceptance": "验收标准"}]
}
边界：不做 AI 设计，不做前端架构
```

## ⑥ AI 架构师
```
输入：PRD + 交互/UI方案 + 调研报告
输出：{
  "model_strategy": {"cheap": "...", "strong": "...", "routing": "simple/complex/fusion"},
  "prompt_templates": [{"name": "...", "template": "...", "variables": [...]}],
  "agent_topology": {"entry": "...", "sub_agents": [...], "handoff_rules": [...]},
  "context_strategy": {"window": "最近N轮+摘要", "persistent": ["项目信息", "用户偏好"]},
  "tool_definitions": [{"name": "...", "description": "...", "parameters": {...}}]
}
边界：不做系统架构，不做前端，不写代码
```

## ⑦ 前端架构师
```
输入：PRD + 交互/UI方案 + 调研报告
输出：{
  "component_tree": [{"name": "...", "children": [...], "props": [...]}],
  "state_design": {"global": {...}, "local": [...]},
  "route_design": [{"path": "...", "component": "...", "auth": true/false}],
  "performance_strategy": {"code_splitting": [...], "lazy_load": [...], "cache": "..."},
  "package_choices": {"ui_lib": "...", "state_mgmt": "...", "router": "...", "css": "..."}
}
边界：不写代码，不做后端，不做 AI 设计
```

## ⑧⑨⑩⑪ 实现层
```
输入：统一架构文档 + 自己对应的任务条目
输出：{
  "changed_files": ["..."],
  "test_results": {"pass": N, "fail": M, "errors": [...]},
  "interface_usage": {"consumed": ["api_contracts[0]"], "provided": ["..."]},
  "merge_ready": true/false,
  "notes": "实现中的取舍说明"
}
边界：不改架构方案，发现架构问题上报不自行修改
各角色只取架构中自己相关的部分：
  - 前端工程师：取前端架构 + 系统架构中前端相关 task
  - 后端工程师：取系统架构 + AI架构中集成相关部分 + 后端相关 task
  - 数据/AI 工程师：取 AI 架构中向量库/模型/数据管道相关部分
  - DevOps 工程师：CI/CD 配置、Dockerfile、部署脚本、监控告警
```

## ⑫⑬ 验收层
```
输入：架构约束清单 + 代码 + 测试结果 + test_cases.json
输出：{
  "passed": [{"check": "...", "evidence": "..."}],
  "issues": [{"id": "..", "severity": "bug/warning/suggestion", "fix_route": "impl/design/note",
              "file": "...", "description": "...", "suggested_fix": "..."}],
  "summary": {"total_checks": N, "passed": N, "failed": N,
              "verdict": "go/no_go", "verdict_reason": "为何 go/no_go"}
}
边界：不写代码，不修改任何文件；fix_route 是建议，最终路由由 Observer 按 verdict 汇总判定
```
