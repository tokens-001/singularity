### ③ 入场动作表（不在你们七条里，从 8.7#3 长出来）

案例 B 的根因是"同一件事两个入口，跑得多的那个忘做全套"。你们的修法是给 `_decompose_and_create_tasks` 补一行——这是点修。结构修是把"进某相位该做的一套动作"挂在流转本身上：

```python
_ON_ENTER = {Phase.EXECUTING: _enter_executing}
def set_phase(self, phase, reason=""):        # 单一入口已有，加三行
    ...
    act = _ON_ENTER.get(phase)
    if act: act(self)                          # 只做内存赋值，禁 I/O / LLM / 可抛的活
    self.phase = phase

def _enter_executing(p):
    p.constraints_checklist = (p.architecture or {}).get("constraints", []) or []
    p.fix_round = 0
```

A5 两条路（`_workflow_phases.py:569` 与 `orchestrator.py:783`）各自的手抄对齐动作删掉。从此**任何第三条路**（重入、新接口、CLI）进 EXECUTING 都自动带全套。幂等性论证过：重入写同值无害；GATE3 design 路走 PLANNING 不经过它。

**验证**：已有的 `test_decompose_fallback_writes_constraints_checklist` 保留（变异即红）+ 新增"合成第三条路"测试（直接 `set_phase(EXECUTING)` → 清单必被写）。**自查**：动作抛异常会打断所有流转（爆炸半径）→ 立规"只赋值不 IO"；测试桩没方法的问题 → 动作内 `getattr` 容错（`effective_constraints` 的教训）。

## 三、只能做一件（第 3 题）

**做对账循环。** 理由三条：**(a)** 它是唯一能发现**未知形状**的仪器——守卫只防 except 这一种基底，而你们 24 小时内的三个案例里只有 A 是 except 形状，B 是多入口、C 是时序，守卫一个都拦不住，对账循环对 B、C 的症状都命中；**(b)** 它把性质清单从散文变成运行时判据（性质 1/4/6/9 直接成为可执行检查）——清单不再是"换架构前问一遍"，而是每 tick 在问；**(c)** 它是 B 族的唯一探测器（第 5 题展开）。守卫排第二、第二天就做——一天活、零运行时风险、阻止形状增殖。

## 四、第四条路（第 4 题）

**有，而且你们七条和我的上一轮答卷都漏了它：把观测者放到进程外。**

你们所有的仪器——告警、聚合视图、对账循环、守卫——**全部住在被观测的进程里**。§57 教过：挂起不是异常，except 拦不住；§65 的现场：`_loop_worker` 停在 `sleep(3)` 空转，任务孤儿挂着——**进程内的仪器看不见进程自己挂死**。一个 30 行的外部看门狗（cron/launchd 每分钟 `curl` admin 状态口 + 检查 `reconcile_stamp` 年龄 + 端口活死 + 通知），零运行时代码改动，专堵"整个进程装死"这个进程内无法覆盖的洞。对账循环设计成"纯盘可查"后，它的判据连看门狗都能复用。

次选两个不改运行代码的：**回放测试**——对账判据在 CI 里对生产 `.qidian/` 快照跑一遍（判据烂掉会在 CI 现形，同时白捡历史违规排查）；**活性套件**——§64 那个"真跑一遍 consolidate_memory 断言无 `is not defined`"的行为判据，推广到所有周期性维护函数，一函数一测。

## 五、最大的误判（第 5 题）

**"成熟方案只能治 A 族"这句话对水位触发是错的，而这个错让你们低估了自己的 1 号方案。**

论证【推断，前提=你们的 A/B 二分】：B 族的定义是"判据从一开始就不成立，没人验过"。水位对账确实不修假判据——但它把 B 族的**后果**（该跑的没跑、该有的没有）变成**缺席信号**：案例 A（consolidator 从没跑过）在水位世界里就是一条"活性缺席"常驻条件，案例 9（计数器永不达阈值）同理。**水位触发不治 B 族的判据，但让 B 族从"不可见"变成"必然可见"**——失败模式从静默变成常亮，而常亮是你们已经有处理机制的（§62：进配置桶）。持久化引擎和结构化并发确实不碰 B 族，你们把三者并在一起判了。

更深一层：**B 族不是一个待"治"的存量，它是每个新判据的出厂状态**——任何新检查出生时都没人验过。所以"治 B 族"不是选引擎，是一条你们已经立了法却没认领的规程：§9.2（每个修复答得出"怎么发现它失效"）。**9.2 就是 B 族的解药，你们发明了它，然后在 §四 里宣布这类无解。**前提若错（若 B 族确有引擎可治的成分），结论变弱但方向不变：水位化仍是最便宜的 B 族显形器。

## 六、"默认怀疑"怎么落地（第 6 题）

**翻转的适用对象是"承诺清单"，不是"代码行"。** 对 561 个 except 逐一翻转必然淹死筛子（你们 §3.3 的数据已经证明）；对**约 30 条承诺**（承诺字段、相位流转、周期维护、产物文件——性质清单第一、二组就是枚举）翻转是可行的。落地形态是**台账**不是告警：

- 每条承诺登记：生产者是谁、证据是什么（带时间戳的文件/字段/心跳）、对账判据是什么、key 是什么。
- **关键设计：缺席驱动的信号天然低噪声**——一个承诺一条常驻条件，兑现即消；事件驱动才按次刷屏。默认怀疑 = 把告警重心从事件转向缺席，淹筛子的问题在信号类型上就不成立。
- 迁移路径：枚举承诺（半天）→ 逐条定义证据与判据 → 对账循环查新鲜度 → except 守卫阻止无痕库存增殖 → 存量 420 只随触碰收敛。
- 翻转自身失败的兜底：缺席判据也可能是 B 族（永不清 → 常亮噪声，§62 的教训）——常驻条件带 TTL，超两周自动升级进"必须处置"的配置桶，不许挂着不管。
- 文化半边：§9.2 推广到特性级——**每个新特性交付时申报"它的证据是什么、谁查缺席"**，让台账随代码长而不是追着代码补。

## 八、评架构（第 8 题）

**8a. 六条判定**：#1 两套驱动——**真问题，中等**，伤害面已被 set_phase 收窄，残余是"认识不同的子集"（进程内可治：`_PHASE_OWNER` 表 + 入场动作）；#2 边沿触发——**真问题，最深的一条**，§59/60/65 全是它的孩子，水位化直接治；#3 多入口——**真问题，案例 B 是实证**，入口收敛可治；#4 内存/磁盘双活——**真但小**，规则可治（"挂在行为上的状态必须落盘"，consolidator 已修）；#5 裸 future——**真但已基本包扎**，wrapper 收尾；#6 零数据库——**不是债，是取舍，且利息已大头付清**【推断】。理由：事务/原子写你们手工建了（#46）、约束用往返测试建了、并发控制用锁建了——**你们在按事故逐条手工重建数据库的功能，而每次重建都产出了超越数据库的一般化规则**（原子写→#46，三态→#44），这些进了防御模式库，是这个项目的核心资产。换 DB 失去 grep（第一排障工具）且要做全量迁移，换回的是已修复的六七条并发事故。唯一现债：**role_probe 这个第二进程已经打破了单进程假设**（#46 就是它撞的）——用"单写者规则"（探针只读）或锁文件收口，别急着上数据库。前提敏感性：若出现多用户/第三写者，此判翻转。

**8b. 要不要改**：**不换进程模型。** 要换的是触发范式和入口纪律——都在进程内。真正需要新进程模型的（中途崩溃续跑、多实例、恰好一次）现在一条都不疼。进程内可改清单：水位对账（治 #2 症状）、入场动作（治 #3 复发）、future 包装（包 #5）、判据落盘规则（治 #4）、相位所有权表（减 #1 伤害）、外部看门狗（堵进程挂死——这条严格说在进程外，但也不需要换模型）。
