## 2. 共用函数

### 2.1 放哪、叫什么

- **模块:`src/singularity/scheduler/_io.py`**(既有 `atomic_write_json` / `load_toml` / `try_parse_json` 所在地,模块头自己写着"全仓 TOML/配置文件加载统一走此模块……不得裸调 tomllib/json.loads"——这批裸调正是违了这条没被管)。
- **名字:`load_json_or_quarantine` / `load_toml_or_quarantine`**。故意不用 `load_json_file` 这种平名:全仓 13 个调用点,名字本身要能读出"读坏会隔离"。既有 `load_toml`(损坏=raise)**保留不动**,web/app.py 靠它工作(§4.1)。
- 依赖方向:skill_loader 在 `skills/` 包,但已有先例(skill_loader.py:40 函数内 import scheduler.config),照同样 lazy import 即可。

### 2.2 契约(先说死,再贴实现)

1. **三态**:文件不存在 → `{} / []`(expect 决定);存在且可解析、顶层类型对 → 解析结果;存在但读不了/解析不了/类型不对 → **None**。空文件(0 字节)按"解析不了"算 —— 纪律就是"只有不存在才当空"。
2. **None 之前函数已做完三件事**:原样字节备份 `<名>.corrupt`(已存在则时间戳轮转,不毁旧证据)、witness(alerts.jsonl,key 按**文件名**聚合,坏两个文件是两条常驻告警)+ log(scheduler.log)双通道出声、原文件一字不动。
3. **不覆写怎么落实**:读函数管不住调用方接下来写不写。纪律拆成两条写在每个调用点:
   - **只读路径**:允许降级成空(`or {}` / `if None: return []`),因为出声+备份已经在函数里发生了,降级是"带告警的降级"。
   - **读改写路径(CRUD/记账/保存)**:拿到 None **必须 raise**,消息里写明备份位置。宁可这一次操作 500,不可拿默认值/空表去重建文件。
4. 出声不能单点:`witness.warn` 自己会吞 OSError(witness.py:73,那是 S5 的形状),所以补 log.py 第二通道;两者都挂时至少 Python 层的 raise 还在(写路径)。
5. **必须在函数体内 lazy import witness/log**:`witness → tracker → _io` 是现成的环,模块级 import 直接炸。

### 2.3 实现草案

```python
# ── 追加到 _io.py 的 atomic_write_json 之后 ──────────────────────

def _quarantine_corrupt(path: Path, reason: str) -> None:
    """读坏文件的统一处置:原样备份 .corrupt(已存在则时间戳轮转),双通道出声。
    备份失败不抛 —— 出声不能因为备份失败而哑,消息里如实写"没备上"。"""
    import shutil
    import time as _time
    from . import witness            # 函数体内 import:witness→tracker→_io 成环
    from .log import warn as _log_warn
    try:
        bak = path.with_suffix(path.suffix + ".corrupt")
        if bak.exists():
            bak = path.with_suffix(path.suffix + f".corrupt.{int(_time.time())}")
        shutil.copy2(path, bak)      # 原始字节 + mtime,不经过任何解析
        note = f"已备份 {bak.name}"
    except OSError:
        note = "备份失败(原文件未动)"
    msg = f"{path.name} 损坏({reason}): {note}, 拒绝当空"[:200]
    _log_warn("io", msg)
    try:
        witness.warn("io", msg, key=f"json_corrupt:{path.name}")
    except Exception:
        pass                         # log 通道已经写过一次,这里别二次抛


def load_json_or_quarantine(path: Path, *, expect: type = dict) -> dict | list | None:
    """读 JSON 状态/配置文件。**三态,不吞**:

      - 文件不存在                        → {} / [](expect 决定)= 真的空
      - 存在、可解析、顶层类型对          → 解析结果
      - 存在但读不了 / 解析不了 / 类型不对 → None
        返回 None 前本函数已完成:① 原样备份 <名>.corrupt ② witness+log 双通道
        出声 ③ 原文件一字不动。

    ⚠️ 调用方纪律(写在这,但**靠每个调用点自觉**):
      只读路径     → 可降级:  `data = load_json_or_quarantine(p) or {}`
      读改写路径   → 必须停:  `if data is None: raise RuntimeError(...拒绝覆盖...)`
      `or {}` 只许出现在"这条路径上没有任何写入"的函数里。
    """
    if not path.exists():
        return expect()
    try:
        raw = path.read_bytes()
        data = json.loads(raw)
    except OSError:
        _quarantine_corrupt(path, "读失败")     # 读不了多半也备不了,函数会如实说
        return None
    except (json.JSONDecodeError, UnicodeDecodeError) as e:
        _quarantine_corrupt(path, f"{type(e).__name__}: {e}"[:80])
        return None
    if not isinstance(data, expect):
        _quarantine_corrupt(path, f"类型不对: 期望 {expect.__name__}, 实得 {type(data).__name__}")
        return None
    return data


def load_toml_or_quarantine(path: Path) -> dict | None:
    """load_json_or_quarantine 的 TOML 版(mcp_servers.toml / fusion.toml 用)。
    既有 load_toml(损坏=raise)保留不动 —— web/app.py 的 fusion 读写靠它自己兜。"""
    if not path.exists():
        return {}
    try:
        with open(path, "rb") as f:
            data = tomllib.load(f)
    except OSError:
        _quarantine_corrupt(path, "读失败")
        return None
    except tomllib.TOMLDecodeError as e:
        _quarantine_corrupt(path, f"TOMLDecodeError: {e}"[:80])
        return None
    if not isinstance(data, dict):
        _quarantine_corrupt(path, f"类型不对: 期望 dict, 实得 {type(data).__name__}")
        return None
    return data
```

## 4. **不该**改成这个的(以及为什么)

### 4.1 `web/app.py:911-936` fusion 配置 GET/PUT —— 已是正确范本,别动

GET 读坏 → `witness.warn(key="fusion_config_unreadable")` + 500,注释原文就是本修法的纪律(「回 `{}` 会让界面显示成空,而下一次 PUT 会拿这份假空去覆盖真的配置文件」);PUT 里 `load_toml` 若 raise 也被接住不落盘。它继续用**会 raise 的** `load_toml` 是对的 —— 别"统一"成新函数,反而把它拆坏。`load_toml` 本身保留。

### 4.2 `_io.try_parse_json` / `apply_json_patch` / `_parse_patch_ops` —— 这是"容错解析",不是"损坏状态"

它们解析的是 **agent 的一次性输出**,不对应任何落盘文件:失败返回带 `parse_error` 标记的 dict / 返回原稿,调用方可见、可追问。清单文档自己已把这类归为"方向对,别改"。给它们套 quarantine 是范畴错误 —— 没有文件可备份,而且"多候选轮着试"本来就是它们的本职。

### 4.3 `_dispatch_crud.py:102-109` `_in_model_library` —— "查不了当有"是有注释的决定

`except Exception: return True` 看着像 fail-open,但 docstring 写明:宁可多留一个"我停用过它"的标记,也不因注册表读挂就丢用户的决定。方向是**保守侧**(多记不丢),不属于 S1。别顺手改。

### 4.4 `api_store.py:105-111` `_seed()` 里的 `except Exception` —— 不同形状

它兜的是 agents.toml **发现过程**的失败(warn 后继续建库),不读 api_store.json 本身;属于 S5/S6 的观测话题。另外那段嵌套 `except Exception as e: witness.warn(...)` 的写法本身可疑,但不归 S1 管。

### 4.5 `witness.py:73` `except OSError: pass` —— S5 的形状,别混进来

它管"告警通道自己挂了怎么感知",是 S1 修法**依赖**的下一层(所以本草案给 noise 加了 log 第二通道)。归 S5 的单子,这里不修。

### 4.6 `mcp.py` 原有的 `_log_warn` —— 不是要清除的对象

修正清单的分类:那行**不是**静默失败。本修法只是把它的通道升级成 witness+log 并把返回语义改成 tri-state;别在评审里把它当"又一处静默"重复计数。

## 5. 遗留风险 / 未决(如实列)

1. **纪律靠自觉**:`or {}` 只许出现在只读路径 —— 这条写不进类型系统。每个 diff 都标了【只读】/【写路径】;落地时评审按这个标签逐个过。
2. `api_store._load_raw` 的降级安全性依赖不变量"所有 `_save` 前必过 `_load`"(现核实成立:125/201/210/231 四个 `_save` 位全满足)。**这条不变量值得在 `_load_raw` docstring 里钉死**(diff 已含)。
3. `.corrupt` 轮转无上限:同一文件反复坏会攒 `x.corrupt.<ts>`。告警在,人来了会清;暂不做轮转上限(没需求先别造机制)。
4. `expect` 只支持 dict/list。现有 13 个点够用;出现新形状时再说。
5. `record()` 拒写期间账本轮空 —— 靠 `key="ledger_corrupt"` 常驻告警盯。若告警页没人看,账本会一直不进账:这是"出声的不继续"的既定代价,不是漏修。
6. `save_toml` 无原子版(mcp/fusion 的 TOML 写侧),半截写仍可能造出下一个损坏文件 —— 记为后续,不混入本轮。
7. 本修法修的是"读坏不装空";**写侧并发覆盖**(读-改-写竞态)是另一个族(_model_discipline 有锁、api_store 没有),不在本草案范围。
