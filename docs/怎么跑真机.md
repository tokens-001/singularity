## 〇、止血与停车（先看这个）

- 🔴🔴 **止血仍在**（09-21 用户原话「这几天太烧钱了，我顶不住了」）：**真机轮暂停，起后端先问一句。**
  **起后端 = 循环＋观察者一起起，立刻开烧**，**底价 ≈ 5 分钟 / 12,373 token**。
- 🔴 **起之前三件事，缺一不可**：
  ① **先看有没有非终态项目**（两种"重启即开烧"：僵尸任务被回收重派 · 「任务清空 + phase 非终态」会在启动那一秒重新拆解）；
  ② **`caffeinate -dimsu` 先上**（机器一睡整轮读数全废，见下面第一条）；
  ③ **改完代码先重启后端再跑**（`debug=False`，没有热重载）。
- ⚠️ **`SIGTERM` 杀不动它**（实测 5 分钟没退）⇒ 要 `kill -9`。取 pid 用 **`lsof -nP -iTCP:5050 -sTCP:LISTEN -t`**
  —— `lsof -ti:5050 | head -1` 给的是**客户端**，09-21 拿它杀错了一个 `com.apple.` 进程。
- ⚠️ `~/projects/singularity` 里有 **2 条存量 stash**（`rollback-protect:b` / `:b1`）—— **不是我的，别 pop**。
  还原一律 `git diff > /tmp/x.patch` → `git checkout HEAD -- <file>` → `apply`；**变异复核的顺序是「改 → 跑绿 → 提交 → 变异 → 还原」**。
- 🔴 **「暂停」和「停」是两件事，别混**：任务级 `POST /api/tasks/<id>/pause` ①**不即时**（每轮开头才读，飞出去的那次调用拦不住）②**占着位子等**（卡住 worker 线程，暂停两个 ≈ 整个池子停摆）③逐任务的，不拦观察者。
  「停」= **给非终态任务写取消标记**（`POST /api/projects/<id>/stop`）⇒ 在飞的下一轮开头退出、排队的一起来就看到、没派的不再被派。⚠️ 语义是**人工取消** ⇒ 以后返工重置时这批**不会被重新拉起**（要接着跑得清标记）。
- 🔴 **③ 现在比 09-17 难得多**：09-17 那次 `done` 是**带着 5 个失败**达成的（旧语义），而 `d7b4d28b` 反转了它 ⇒ 今天要求**一个任务都不失败**，而历史失败率很高（09-26 13/14 · 09-17 5/11）⇒ **这是判据变严，不是系统退步**。

### 盘上项目现状 —— **别抄名单，跑一条命令**

```sh
.venv/bin/python scripts/projects_state.py      # 退出码 1 = 有项目会开烧 ⇒ 别起后端
```

**判据不是"记名单"**（09-29 实测：上一版手抄的表列了 4 个、盘上 12 个，而它读起来像"核过了"）：
**停 = `project.halt_state`**（人叫停 ∨ 有 FAILED/ROLLED_BACK 任务 ⇒ **派生**，不落盘）。
两条"重启即开烧"：① 僵尸任务被回收重派（要**非终态**任务）② 「任务清空 + phase 非终态 ⇒ 启动即拆解」（要 `task_ids` 空且没停）。

## 一、起跑

- 🔴🔴 **第一步永远是 `caffeinate -dimsu`**（09-28 定）。
  **机器一睡，整轮读数全废**：墙钟照走、进程不动 ⇒ 任务预算被吃掉、界面显示"任务在跑 900 秒零产出"、**看门狗一条都响不了**（连内核读超时也不推进）。09-28 凌晨那四轮就是这么废的。
  **判据**：起前 `pmset -g assertions | grep caffeinate` 看得见、`pmset -g log | tail -5` 没有 `Entering Sleep`；**跑完 `kill` 掉它**。
  ⚠️ **别拿"我盯着呢"当保险** —— 实测 `00:50:19` 放开断言、`00:50:24` 就睡。
- **起后端**：`cd ~/projects/singularity && nohup .venv/bin/python -m singularity.web.app > /tmp/qidian.log 2>&1 &`
- 🔴 **改完代码必须先重启后端再跑真机**。判据：`ps -o lstart= -p <pid>` 要**晚于** `git log -1 --format=%ad`。
  09-17 踩过：跑着的进程是 01:40 起的，修复 02:12–02:28 才提交 ⇒ **整轮跑在旧代码上，得出"修复没用"的假结论**。
- 🔴 **每轮开局先打 tag**（`git tag -a round-<日期>` 打在开跑那一刻的 HEAD），**同一刻顺手存清单快照**：
  `cp ~/OPEN.md docs/OPEN快照-$(date +%Y%m%d%H%M).md && git add docs/ && git commit -m "轮次快照"`。
  用途：`git describe --tags` 比出来的 N 个提交 = 这轮带着但没验过的修复。⚠️ **别挂进 hook 每轮写**（会让工作区常脏，把真红变成假红）。
