## 一、怎么设计的（**种一个基线坏测试**）

在这两个项目的**基线**里各 commit 一个故意失败的测试：

```python
def test_planted_baseline_broken_20260929():
    """基线里本来就有的一个坏测试（2026-09-29 验证轮种下）。"""
    assert False, "基线坏测试：这一条故意失败"
```

⇒ 产物门禁**必然**失败一次 ⇒ 逼出「测试失败 → 重试」那条路。
**判据**是修复前后**可对比**的：修复前（`round-20260928j`）落盘的证据是
`tests failed: .......F......  ____ test_common_options_ma` ——
**断在测试名中间，断言一行都没有**。

⚠️ **两轮都以 T1 失败告终，这是设计内的**：那个坏测试不属于任何任务声明的产出文件
（T1 的 `estimated_files` 只有 `strkit.py`），而**模型两次都正确地没有去改它**
（原话：「没有改动 `test_planted_baseline_broken_20260929.py`」）⇒ 它必然一直失败。
**这轮要验的是"失败之后发生了什么"，不是"能不能跑通"。**

## 四、我自己的两条探针**都没有判别力**（关键教训）

我原本设了"最强判据"：**模型在重试后的输出里会不会提到那个种下去的坏测试名**。
两轮都"提到了"，但**这个判据证明不了任何事**：

| 轮 | 我当时的判读 | 完整工具事件显示的真相 |
|---|---|---|
| a | 「模型提到坏测试 ⇒ 它看见了反馈」 | 它是 **`read_file` 直接读了我的文件**（文件在根目录，`ls` 一眼看见） |
| a | 「模型自己跑了 pytest」 | **假阳性** —— 我的过滤串 `pytest` 命中的是 `.gitignore` 里的 **`.pytest_cache/`** |
| b | 同上 | 还是 `ls` + `read_file`（`read_file(结果 420 字符)` 里就是那个文件的 docstring） |

⇒ **判据要能区分"信息从哪来"**，否则"提到了"什么都证明不了。
要真判别，那个坏测试得**放在模型不会顺手翻到的地方、名字也不许有描述性**
（如 `tests/test_qq7.py`）—— **没做，下次再说。**

## 五、撞出的新问题（**已登记 `~/OPEN.md`，待拍板**）

🔴🔴 **单文件小改动永远拿不到测试反馈。**

`_review.run_post_exec_checks` 第一句是
`if validation.action == "pass" and changed and not _trivial:` ——
**改动被判"小改动"（单文件 ∧ diff < 50 行）时，整段"跑项目测试 + 多模型审查"被跳过。**

- `round-a`（单文件 `greeter.py`）就撞在这上面：
  `unverified[0]` = 「**审查已跳过: 改动被判为小改动(单文件, diff<50行) — 未跑项目测试**」
  ⇒ `quality["test_result"]` 没被设 ⇒ **`55dfb78e` 那条修复一个字都不会说**。
- 而这类任务的测试失败**是真实存在的**：产物门禁（`supervisor._check_artifact`）
  **照样跑了全量 pytest 并失败**，判词走 `tracker.transition(FAILED, error="QA:fail: …")`
  —— **那是终态，模型看不到**。
- ⇒ **模型在飞的重试是它唯一的纠正机会，而小改动这条路把那个机会的信息清空了。**
  和 round-j **同一个病**（判了失败、原因没送到），换了条路复发。
- 🔴 **同族第三例**：`_check_artifact` 把完整 `test_result` 存进 `evidence["tests"]`，
  而 `reason` 只取一句 `tests_failed_msg`；`evidence` 除了 `hard` 标志**没有任何消费者**
  —— **存了，没送**（与 `data_model` / `estimated_files` / 重试反馈逐字同形）。

⚠️ **没改**：一个数据点 + 是行为/成本权衡（给每个单文件改动都跑全量测试要花时间）。
