## 一、状态与推进

### 1. 写盘的状态，必须有人负责推进它

任何被持久化成"进行中"的东西，要么有明确的推进者，要么有兜底回收者。**"写下来"和"有人管"是两件事**。

**怎么查**：搜出所有"写入进行中状态"的地方，逐个问 —— **下一跳是谁？** 答不出来就是孤儿。

〔§65 先改状态后登记 · §63 执行器不看表 · §9 清理只发信号不等停稳〕

### 2. 终态没有**默认**出边；显式重置必须单入口 + 留痕

一旦判定完成 / 失败，不许被后面的逻辑改回去。

⚠️ **2026-09-13 改措辞**：原来写的是"终态**不该有出边**" —— **太绝对，跟实践对不上**。
`tracker._TERMINAL_EXIT` 是**白名单**，`GATE3 打回`这类显式重置是**合法**的。
真正的规则是防御模式 **§1** 那句：**默认路径不能改判，显式重置必须显式写 `force=True`。**
（性质跟规则打架时，以规则为准 —— 规则是从血案里长出来的。）

**怎么查**：画状态机，看终态的出边**在默认路径上**有没有；有的话，是"重开"（显式新状态、
单入口、留痕）还是"改判"（同一状态的复写）？

〔§1 终态可以被改判 · §2 QA 门禁排在 DONE 之后〕

### 3. 顺序必须由机器保证，不靠调用方自觉

"A 必须在 B 之前"要写成**结构约束**（状态机的边、前置校验），不能写成注释里的约定。

**怎么查**：找所有写着"这里一定要先……"的注释。**注释不是约束。**

〔§2 · §5 同一动作有多条入口 · §19 公共约定两侧都要遵守〕

### 4. 「发出」和「完成」必须能分辨

不许把"我发了信号"当成"事情做完了"。发信号的地方，要么有完成确认，要么明确承认自己是异步的。

**怎么查**：每个 send / notify / submit 的下一行，有没有对应的 settle？

〔§9 · §65 · §28 API 返回 200 却没接真实动作〕

### 21. 「等它成功」的判据，必须同时答出「它永远等不到」怎么办

"依赖全部 DONE 才放行"、"等这个 future 完成再合并" —— 这类判据只写了成功那一半。
**失败也是终态**，它同样意味着"它不会再变了"。只认成功的判据，会在依赖一失败时**永久 defer**：
合并请求永远满足不了 ⇒ 任务永远留在队列里 ⇒ 调度循环把"队里有东西"当成"有活干"、
全速空转，而那个任务就挂在 `RUNNING` 上再也不动。

**怎么查**：搜所有"等成功"的判据（`!= DONE`、`== SUCCESS`、`all(...)`）逐个问 ——
**它失败了怎么办？** 到终态（成功 / 失败 / 放弃）就该放行或降级；"等不到"要另行有出路。

〔§77.1 依赖失败 ⇒ 合并队列永久 defer ⇒ 调度永久自旋、任务永久卡 `RUNNING`〕

### 22. 循环的继续条件，必须是「有没有进展」，不是「表里有没有东西」

"队里有活"和"有人在干"，在循环眼里长得一模一样。只要有任务在跑就一点不睡，
碰上那种永远不会有进展的活，就是**全速空转几十分钟**（真机实测：2 分钟 1731 圈、44 分钟 CPU），
而且**跟卡死无关，平时就这样** —— 任务少、轮次短的时候没人注意。

**怎么查**：每个 `while True` / 调度循环，问它**这一圈比上一圈多了什么**？
答出来的是"表里非空"就是没满足。睡觉条件要挂在"**这一圈真推进了没有**"上。

〔§77.2 调度循环没有退避（常态）· §77.1 外层把"队里有东西"当成"有活干"〕

### 23. 状态要成对设计：进得去，就要有出得来、而且**人能触发**的路

"进得去出不来"的状态等于一个黑洞：任务永远卡在那儿、项目再也推不到下一步，
而**接口层一个能挪它的方法都没有**（`retry` 只收 FAILED、`cancel` 只是把状态标成 FAILED
—— 那是假的）。写转移的时候只想了怎么进去，没写谁负责把它转出来。

**怎么查**：画状态机，逐个状态问两句 —— ① **谁负责把它转出去？**
② **转不出去时，人能怎么办？**（第二条要拿手点一遍：真的有个 API 能点吗？）

〔§77.9 `resolve` 解完冲突后任务永远卡在 `conflict_held`〕

## 二、失败必须留痕（默认怀疑）

> **这一族是全部 85 条里最大的一族** —— 按"静默类"措辞数，
> **09-13 量过一次：当时的前 66 条里 20 条（约 30%）属于它**（这个比例没重算过，别当新数用）。
> 也是唯一一族能靠**换默认**从根上解决的。

### 5. 任何失败路径，必须留下可聚合的痕迹

接住一个异常，**要么出声、要么上抛，不许静默吞掉**。而且痕迹要能被**聚合**看见 ——
一条孤零零的日志等于没有。

**怎么查**：`grep -n "except" `，逐个看后继。⚠️ 2026-09-13 量过：全仓 561 个 `except`，
约 **420 个（74%）**既不出声也不上抛（估算）。**这条是当前最大的债。**
⚠️ 09-20 补：**读路径也算失败路径** —— `read_task` / `ready_tasks` 那种"读不出一律 `return None`"
让一条 `RUNNING` 任务变成"界面上根本查不到、但状态是 running"的幽灵；**静默删一条坏心跳**
也是（一次撕裂 = 一个真卡死的任务从告警系统里消失）。
⚠️ 还有一个反过来的坑：**留痕要能去重** —— 挂在"每 2 秒扫一遍全部文件"的读路径上，
一份坏文件会每 2 秒刷一条告警。

〔§48 NameError 被吞成默认值 · §32 静默兜底=编造数字 · §25 fail-open · §55 痕迹和账一起消失 ·
§82.1 tracker 读路径静默吞错 ⇒ RUNNING 幽灵 · §82.2 心跳静默删〕

### 6. 「没有数据」和「数据说没问题」必须能分辨（遥测三态）

三态：**有值 / 缺值（`None` = 不知道）/ 压根没发起**。**`None` 不是 0** ——
把"拿不到"渲染成默认值，等于替用户做了决定。

⚠️ **2026-09-13 点名**：这一条就是 §59 / §63 咬了三次的那个"**上报口径 ≠ 事实**"，
以前只在正文里隐含，没在标题上显形。**字段是 `None` 时先问"是没发生，还是没落盘"，再下结论。**

**怎么查**：所有承诺类字段，默认值是什么？"没发生"和"发生了但失败"长得一样吗？

⚠️ **09-20 补第三种走样：兜底值也要有形状。** 一个"字段全缺"的兜底对象，在只读字段的渲染器里
**和"还没有数据"长得一模一样** —— 那不是兜底，是把故障藏起来了（前端还不认识 `parse_error`
这个标记 ⇒ 一个字都不报）。

〔§44 承诺类字段三态可分 · §47 代理漏字段→判据恒假 · §33 缺失值渲染成 0 · §3 写的字段≠读的字段 ·
§77.10 调研报告解析失败 ⇒ 界面上是个空框〕

### 7. 一个地方坏，不许连坐

一个回调、一个成员、一个模型抛异常，不能让其它无关的活儿跟着饿死。

**怎么查**：每个循环体里的异常边界 —— 抛出去会带走谁？

〔§10 一个回调抛异常饿死后面的 · §62 池太小导致裁判告警常亮〕

### 8. 「不是异常的失败」也要算失败

挂起、重试预算耗尽、超时后线程还活着 —— **`except` 拦不住这些**。它们必须另有出口。

**怎么查**：列出所有"不会抛异常但会永远不返回"的路径，问它靠什么被发现。

〔§57 挂起不是异常 · §59 超时≠停了 · §17 超时设太短〕

### 9. 告警是**累积**的 —— 读的人必须能对照修复时间分辨"已修的"和"现存的"

⚠️ **2026-09-13 修正**：原来标题只写"必须带时间"，被指为**桌椅级配置**（对）。
真规则是防御模式 **§42** 那句：**告警不会自己消失，所以"看到一条"不等于"它正在发生"**
—— 读的人得拿**修复的时刻**去比，而写的人得保证**时间维度在**。
两者缺一，就会出现"把已修的问题当现存 bug 再查一遍"。

**怎么查**：随手翻一条告警，不问别人、不看代码，**只凭这条记录本身**能不能判断它现在还在不在发生？

〔§42 翻告警不看时间 = 把已修的当现存 bug〕

⚠️ **09-20 补一句同族的**：**一次修复推翻了旧结论时，要把按旧结论写的账（清单 / 记忆 / 文档）
一起改掉。** 那次有两条旧结论被推翻，而它们同时出现在 `~/OPEN.md`、记忆正文、演化史三处 ——
**格式对、内容旧，比缺失更坏**（下一轮会按旧账把验过的事再验一遍）。同族还有一次：
本文第 19 条引的"替代判据"在 09-19 被实测推翻，已在原文里划掉 —— **旧结论不做标记就会继续被引用。**

〔§76 「修复推翻旧结论」规则 · §77.3 的 2026-09-19 更正〕

### 24. 不同的来路，必须在数据里长得不一样 —— 失败不许长得像成功

三处同族，一句话：**"模型答完了"和"被我们掐断的"，在返回值里一模一样** ⇒
掐断的被当成偷懒、算到模型头上；"我们自己的超时"和"用户点了取消"共用一个标记 ⇒
超时被记成用户取消；"读不到"和"没有"都回 200 + 空数据 ⇒ 前端那条三态在最该起作用时必然失效。
**第三种最难查 —— 它在线上长得和成功一模一样。**

**怎么查**：每个返回值 / 标记问一句 —— **它能不能区分出所有产生它的来路？**
失败的形状只有三种（抛异常 / 非 2xx + 原因 / 200 + 空数据），
**"空数据"这一种绝不许用来表达失败**；判据落在 `catch` 上时，要去后端确认"失败时它真的抛吗"，别假设。

〔§79 "被我们掐断的"被算到模型头上 · §82.3 超时写的"停"标记冒充用户取消 ·
§70 拒写/失败的原因在端点层被丢掉〕

### 25. 诊断证据、以及「我唯一的判据」，都不许被自己删掉

心跳是"在不在跑"的唯一凭据，任务文件是"有没有这个任务"的唯一凭据，
取消标记是"谁叫停的"的唯一凭据。**删掉它 = 删掉判据本身**，而剩下的系统状态**长得和健康一模一样**。
同族的第二面更阴：**告警轮转把你要用来诊断这次故障的证据，当成"过量的垃圾"清掉了**
（开跑前 2714 行 → 事后 2175 行）—— 一个**只在异常时才触发**的机制，不能拿异常的证据去腾地方。

**怎么查**：所有 `unlink()` / 轮转 / 截断 / "丢弃未知键"的地方，问两句话 ——
① **这是不是我唯一的判据？** ② **删之前，告警通道收到话了吗？**
（换成 `logging` 等于没修 —— 静默删输入说的就是"告警通道没收到"。）

〔§82 四个静默失败：共同形状是删掉/丢掉自己唯一的输入 · §77.4 告警轮转把诊断证据冲掉了〕

### 26. 「出声」不等于「拦住了」

当一条禁令是某条路的**前提**时（"委员会 = 纯文本出方案、别动磁盘"），
**拦不住就别让它跑** —— 出条告警然后照跑，等于前提已经不成立、活还在往下干。
代价是实测过的：调研员在项目仓里把整个项目实现完了；合成 agent 把目标项目的架构
写进了奇点自己的 `docs/`。**"出声"只适用于"拦不住的后果可接受"**那种场合。

**怎么查**：每个"检查不通过就 warn 一下继续跑"的地方，问 —— **这条检查是不是后面那条路的前提？**
是的话，它的正确行为是 `return None` / `continue` 试下一个 / 全不行就"无可用 agent"（fail-closed），
**不是 warn**。

〔§76.2 「禁工具」是四条路的共同前提，而它拦不住时只是出个声〕

## 三、判据本身必须可检验

> 这一族**框架治不了**（换持久化引擎也一样）。药是纪律：**每个修复都要答得出"它失效了谁会知道"**。

### 10. 每条判据都要答得出「它什么时候会失效」

答不出来 = 这条判据没写完。**守卫测试还要变异验证过**：把 bug 放回去，它真的会红。

**怎么查**：对每条新加的检查，问"它在哪些输入上会沉默？"

〔§九 9.2 修复交付标准 · §51 强制输出落在循环边界外 · §64 F821 守卫瞎了〕

### 11. 守卫自己也要有「盲区检查」

守卫会瞎：一条 `from X import *` 就让 F821 对**整个文件**闭嘴（全仓 10 个文件在盲区里）。
**"检查跑过了"不等于"检查在那儿有效"。**

**怎么查**：这个静态检查，在什么语法形态下会拒绝报错 / 静默跳过？

〔§64 · §31 静态扫描"0 引用"≠"没人用"〕

### 12. 判据的输入必须真的会被写

**字段有值 ≠ 有人写它**。契约漂了、只有一半路径在写、写进去的名字查不到 —— 判据都会恒假且**看起来正常**。

**怎么查**：这条判据读的每个字段，**写出它的地方有几处**？是不是所有产生它的路径都写了？

⚠️ **09-20 补两处同族的**：一个"约定文件"要能回答**"谁写它"**（`test_cases.json` 有三个读者、
全仓没人写 ⇒ `if path.exists()` 恒假 ⇒ 集成测试**从来没跑过**，而且静默）；
架构声明的约束里指定了测试文件名（`constraints[].check.argv`），**执行器上下文的构造只传了
`rule` 的文字、没传 `check`** ⇒ 干活的人从头到尾没见过那个文件名 ⇒ 10 条约束 `ran=10 passed=0`。
**加一个"读者"之前，先确认"写者"存在，而且写者知道要写什么。**

〔§3 · §47 · §37 流式不带用量 · §38 只统计一部分路径 · §53 记账的调用点=覆盖面 · §54 记账名要能查到价 ·
§76.3 一个文件只有读的人没有写的人 · §77.7 判据要的输入没传到产出它的人手里〕

### 13. 不许有单向棘轮

只增不减的计数器 / 永不归零的状态，能把系统**永久锁死**。

**怎么查**：所有计数器，有没有减回去的路径？

〔§45 单向棘轮 · §35 折叠只重算今天会重复计〕

### 27. 判据要量「实际」，不能量「声明」

一整夜挖出七个形状，收口时发现是**一个病在七层上复发**：任务说「我在跑」（状态字段），实际没人管它；
调度循环说「我在转」，实际没有进展；合并队列说「我在等依赖」，实际那个依赖永远不会来；
告警说「我出声了」，实际没人听；观察者说「我盯着呢」，实际喇叭是空的；
代码仓说「这是我的源码」，实际一半是字节码。**每一层的判据都在量「声明」（状态字段、登记表、
文件名、消息数），而故障永远发生在「声明与实际之间」** —— 所以每修一次只覆盖想到的那几处，
**一直会有新的一处**。

**怎么查**：对每条判据问两句 —— ① **它读的东西，故障时会不会跟着变？**
（"在表里"证明的是"有人登记过它"，不是"有人在干它"）② **我是不是在拿"我自己的声明"证明自己？**
最典型的一条：**对账时不能拿登记表当实际。** 解法不是再加第 8 个 guard，是定期加一层对账。

〔§77 收口：每层都在用"我的声明"证明自己 · §77.3 孤儿探测量的是登记表 · §68 写侧护栏查在读之前〕

### 28. 先问「这个信号，故障的时候到底会不会变」

同一个病咬了四次，**四次都不是阈值选错、是信号选错**：`read=` 量的是"两次读之间"，
服务端一直发字节就永不触发；按行读的循环，服务端吐字节凑不满一行就一次都不进；
"按批字节看表"的总时长判据只管时长、不管有没有用 ⇒ 一次调用可以烧满 240s 而**零产出**。
**"又收到一包字节"不算进展，变长才算。**

**怎么查**：写判据前先答一句 —— **故障的时候，这个量到底是变大、变小、还是不变？**
答"不变"就说明它量错了东西。再加一问：**这条"总时长"的尺，会不会被"有流量"重置？**
会，就换个载体（`iter_text()` / 定时器 / 独立线程）；⚠️ 而且**必须是"抛"，不能是"出声后照常返回空"**
—— 返回空会被上层读成"这次调用成功了、只是模型没说话"。

〔§73 判据的检查点挂在"事件到达"上 · §75 量"有没有字节"而不是"有没有可用进展"〕

### 29. 判据要挂在对的对象上：跟它管的动作**同层**，且卡在**数据自己的形状**上

两个走样，一个病：**判据挂错了对象。**
① **层不对** —— 任务级的刀，拿"每次调用归零"的计时器去挡：收尾逻辑是对的，
装在一个**永远走不到的层**上（每 dispatch 归零一次，生产值下永不触发）；
闸门装在**自己那一条调用方**上，没装在选路的**下游汇合点**上（测试全绿、变异也过，钱照烧）。
② **维度不对** —— 拿"**这一轮**带不带 `tools`"去判"**这条消息**要不要带 `reasoning_content`"，
而该看的是**这条消息自己带不带 `tool_calls`**。拿"当前的环境"判"数据该长什么样"，
会在环境中途变化那一刻产出**自相矛盾的历史**。

**怎么查**：每个守卫问三句 —— ① **它管的那个动作发生在哪一层？我装在同一层了吗？**
（"我装在最后一道了"要先**列全调用方**再说）② **它该看的是"这条数据自己的形状"，
还是"现在外面是什么配置"？** ③ 这个计时器**在什么情况下会重置？重置的那一方知道吗？**

⚠️ **两条挂在时限/阈值上的补充**（09-20 补）：
- **"用一个小值验过"会把"层错了"完全掩盖。** §63 是拿 `QIDIAN_EXEC_BUDGET=15` 验的 ——
  15s 档下**每一次 dispatch 都会超预算**，所以收尾必然触发，"每 dispatch 归零"这个形状**根本露不出来**。
  ⇒ 别把"这次验证用的值"和"生产值"混着下结论。**用小值验，验不出"层错了"。**
- **只判"到没到点"不够，要配一条"够不够用"。** 预算还剩 **6 秒**是**正数**、判据放行，
  于是照样发起一次注定空的调用 —— **"太小也是没有"这个区间没人管。**
  ⇒ 阈值类判据要同时答"到没到点"和"够不够用"。

〔§67 预算的时钟原点和消费者不在同一层 · §78 闸门装在错的层 · §85 判据卡错了维度 ·
§77.8 排队等的时间被算进执行预算（`cap=6s` 照样发起调用）〕

### 30. 判对了症状、判错了主体 —— 就会修在不生效的地方

"半成品模块 + 名字不存在"这个**症状判对了**，**主体判成"跨线程竞态"**，其实是**同一线程重入** ——
于是加了一把 RLock，而 RLock 同线程放行，**从原理上就挡不住**。更糟的是"改了、看起来合理"
把它**盖了三天**，下次还会先怀疑锁不够。同族一句：**在生产值上就是"不生效"的守卫，
先怀疑它装错了层，再怀疑阈值** —— 调参（90 → 180）永远修不好"它压根没跑"。

**怎么查**：① **能挂探针量出调用栈时，先量再改**；"读码推出来的形状"要标清楚是推断，不是结论。
② 改完问一句：**要是我没改对地方，这个改动看起来会不会一样合理？**

〔§81 惰性 `__getattr__` 把 importlib 的探测当成请求 · §67 规则 2：不生效的守卫先怀疑层，别调参〕

### 31. 先定位缺陷的可见性层级，再选检测手段

缺陷分三层：**终态可见**（跑一轮就露）/ **单次不可见、跨运行聚合才可见**（恒默认值、判据恒假、
契约漂移 —— **跑一百次也看不见**）/ **聚合也够不着**（竞态、时序、"加两行诊断就不复现"）。
**手段和层级错配时，缺陷等于不存在。** 最常错的是第二层：拿"跑一轮"去验一个跨运行才可见的缺陷，
会得出"没问题"（判据挂在**每次重启归零**的模块级变量上 ⇒ 永远到不了阈值，功能从未执行）。
⚠️ 第二层还要求**"聚合视图"真的存在** —— 告警平铺着放，第二层的缺陷和噪声没区别。

**怎么查**：动手修之前先答 —— **这个缺陷属于哪一层？我打算用的手段够得着那一层吗？**

〔§9.1 缺陷的不可见性分三层〕

### 32. 验证的场景，必须和故障的现场同构 —— 否则「没红」什么都证明不了

同一个错误的四种长相：① **测试替代码把洞填上了** —— 每条"写侧拒写"用例都先手动读一次坏文件
（那行**正是缺陷的前提**，被固化成了前置步骤），于是测试在替代码填洞、再断言"洞不存在"；
② **那条路压根没被走到** —— 项目里任务全是终态，执行层 1 秒冲过，逐任务的那条路一次没走，
告警三条全空，"看着像修好了，其实是没跑到"；③ **探针没有判别力** —— 六个探针的形状
都不是真机那个组合，"六次都没红"什么都证明不了；④ **触发条件被改掉了** ——
泄漏在我的修复之前先被配置改没了，复现时必须**先把配置恢复成触发它的那一份**。

**怎么查**：每次"验过了 / 没复现"，先答三句 —— ① **这条路径真的被走到了吗？**
② **我的场景和真机差在哪？**（要测**第三方库的行为**必须用真的那个库，手搭的替身只会把我猜的假设喂回给我）
③ **前置步骤里，有没有哪一步是生产里不会发生的？**（步骤 1 的那种）
⚠️ 同族：**"`git status` 干净" ≠ "跑的是干净的代码"**（源码还原了、字节码还是变异过的那份）。

⚠️ 还有最阴的一种：**测试断言的就是 bug 本身。** 那条"不带工具时照旧剥掉 reasoning、对别家零回归"
的用例，**拿的偏偏是带 `tool_calls` 的消息** —— 它钉住的正是这个 bug，
所以"测试绿"和"行为对"是两件事（§85.7，已反向重写）。

〔§69 测试把缺陷的前提固化成了前置步骤 · §78.1 路没走到 / 配置被改掉 · §85.2 六个探针全 200 ·
§85.7 那条测试钉的正是这个 bug · §71 变异留下的脏 `.pyc` · §73 规则 4：回归用例要起真 HTTP 服务器〕

### 33. 「留证据的通道」要在出事之前建好

一条 400 从 09-15 查到 09-19，六种形状全试过都查不出；而**加落盘的那一刻**（认不出来的 400
落一条请求体原文、107KB）**就查清了** —— 这轮真机它第一次响。没有它，这条还会继续无头。
**查不出，往往是因为没留现场，不是因为没有原因。**

**怎么查**：对每个"偶发、复现不了、只能等现场"的故障，问 —— **现场那条路上落盘了吗？**
落的是什么（原文，还是被加工过的摘要）？够不够下一次拿它**直接复现**？
⚠️ 同族：**进程无声消失且没有 traceback 时，日志里一个字都不会有** —— 要**换个地方找**
（macOS 崩溃报告），别在 `alerts.jsonl` / `logs/` 里翻。

〔§85.3 现场是怎么留下的 · §74 整个后端进程无声消失：去崩溃报告里找〕

### 34. 批量改代码，定位只能来自**机器给的精确坐标**

一晚栽三次，都是**"形状匹配"顶替了精确坐标**：① 自动 `--fix` 把**再导出**当死 import 删了 ⇒
53 个测试文件 ImportError（而"全仓有别的模块从这儿 import"那句话**就写在注释里** ——
**注释不是判据，工具不读，我也没读**）；② 规则报的是**列号**，我按"位置"猜 ⇒
把**有用的那个变量**改掉了、整条检查失效；③ 推导式**跨行**，我按行号只换了一行 ⇒ 3 条
`undefined name`。**"形状匹配"在一个文件里够用，在一次几百处的批量里就是抽样 ——
而抽样漏掉的那一处，测试不一定抓得到。**

**怎么查**：动手前先问 —— **我要改的那一处，是工具点名点的（列号 / 全部出现位置），
还是"这一行看起来像"？** 别一次性 `--fix` 全仓，分文件分规则、每步之后跑测试。
⚠️ **同一个形状在"变异实验"里也咬人**：不红时**先怀疑变异有没有改到被测那一行**
（同一句话在文件里出现两次，按字符串匹配就会打偏）；**退出码 1 = 有测试失败 = 红对了**，不是"挂了"。

〔§83 批量改代码时判据被形状顶替 · §76 验证时踩的三个坑（变异打偏 / 退出码误读）〕

### 35. 没绿过的门，等于没有门

F823 / B023 这两条**不是风格债、是活的缺陷**（一条让最该留痕的告警一跑到就抛
`UnboundLocalError`），能在债里躺那么久**是因为门从来没绿过**（CI 前 120 次运行全 failure，
后面几步每次被 skip）。**清债不是保洁，是把没人看的那份报告重新摊开。**
⚠️ **别为了让门变绿改成 `|| true` / `continue-on-error`** —— 那是把红藏起来。
同族：**"看着像绿了"和"真绿了"是两回事** —— 那次告警三条全空、看着像修好了，其实是**那条路没跑到**。

**怎么查**：① 每个检查问一句 —— **它上次真的绿过吗？**（静默 SKIP 的检查 = 没装）
② "这是风格债、先放着"要慎说 —— **F 类（pyflakes）值得逐条看**。

〔§84 清 lint 债最值钱的一笔：债里藏着真 bug · §78.1「看着像修好了，其实是没跑到」〕

## 四、单源

### 14. 每件事只能有一个定义处、一个入口

- **一个定义处**：同一份契约有两份拷贝，必然漂（schema 漂了 → 字段按构造必丢）。
- **一个入口**：多条路做同一件事，**必然有一条忘了做全套**，而且那条通常是**跑得最多的那条**。
- **"没人引用"≠"没人用"**：动态引用、延迟导入、反射，静态扫描看不见。

**怎么查**：① 同一份结构定义了几次？② 同一件事有几个写入者？③ 改/删一个字段，
全仓调用点扫了吗（静态类型挡不住这个）？

〔§61 两份 schema · §5 多条入口 · §60 建任务两条路只有一条写清单 · §29 硬编码覆盖配置 ·
§30 字段语义复用 · §66 删字段没扫调用点 · §40 `Cls(**row)` 载入路径 · §39 整行重建擦掉手填 ·
§27 循环 import · §31 · §82.1 `Task.from_dict` 裸 `cls(**d)` ⇒ 多一个键就读成 `None`〕

### 36. 不变量必须在**读写两侧共用同一个判据**

"`_` 开头是元数据键的保留前缀"这条规则，读侧认（`_load` 跳过）、写侧也认（`_save` 保留），
**只有 `add()` 不认** ⇒ `POST` 回 200、**写进文件了**，然后列不出来、删不掉（`remove()` 压根看不见它），
只能手改 `.json`。**不变量写在哪一侧，另一侧就是洞。** 两边各写一遍 `startswith("_")`
迟早会漂 —— 而**这个 bug 本身就是"判据只在一边"造成的**。

**怎么查**：每个不变量（保留前缀 / 只读字段 / 必须是某枚举 / 名字必须匹配某正则）问一句 ——
**它是"一个函数"，还是读写两边各写了一遍？** 各写一遍的，提成一个共用函数给两边调。

〔§76.1 不变量只在读的一侧执行 —— 写侧没拦〕

## 五、边界

### 15. 不可信的东西不许进 shell / 路径 / 环境

模型输出、外部输入、异常文本 —— 都不能直接拼进命令、当路径用、或塞进环境变量。

**怎么查**：所有拼字符串的地方，来源是什么？

〔§21 环境变量暴露给不可信输出 · §23 外部输入拼 shell · §22 unlink 删链接形态路径〕

### 16. 每个执行都要在「它该在的目录」里跑

漏传工作目录 = 在最不该跑的地方跑（调研员往主仓写文件就是这么来的）。**没有 cwd 就该拒绝跑。**

〔§49 cwd 漏传 · §6 worktree 路径基准 · §7 工作区是脏的〕

### 17. 拿不准就往保守缩（fail-closed）—— **但先分清是哪种判据**

判据取不到、角色查不到、配置缺失 —— **选更严格的那一边**，别默认放行。

⚠️ **2026-09-13 细化（外派答卷指的张力，核实成立）**：这条跟我们的实践中
**有张力、但不是矛盾** —— 实践里早就分了两类，清单没写：

| 判据类型 | 取不到时 | 为什么 |
|---|---|---|
| **拦门的**（放不放行、能不能跑） | **fail-closed**（拦住） | 放行一个不该放的，代价不可逆 |
| **读数据的**（报告里的一个数） | **fail-visible**（显式留空/报未知） | 编一个默认值 = 编造结论；而"拦住"会让整个功能不可用 |

典型：`_qa_verdict_from_raw` 取不到结论 = `未产出`（**拦门**）；
`effective_constraints` 取不到清单 = **兜底 + 出声**（**读数据**，不能直接拒跑）。

**怎么查**：每个 `is None` / 异常分支，先问"**这是拦门还是读数**"，再问"返回值对不对"。

〔§25 fail-open 漏报 · §47 · §57〕

### 18. 资源要么用完清，要么有主；隔离要按进程算

- 临时目录 / worktree / 队列，**要么有 owner 负责清，要么有兜底收割**。
- **"确定性路径 + 线程锁"不等于进程安全** —— 同一台机器上跑两个进程就破了。

**怎么查**：① 每个 tmp 资源的下场是什么？② 这里假设"只有我一个进程"吗？

〔§12 资源没清 · §8 SSE 重连不清理 · §46 确定性 tmp + threading 锁 ≠ 进程安全 ·
§41 模块级单例不吃隔离 · §56 单例构造时冻住路径 · §13 跨线程改共享状态〕

### 19. 观测者自己必须有活性信号，而且**它的死亡要能被进程外观测**

**这条 2026-09-13 补，来源是外派答卷的第 7 题** —— 它指出的缺口核实成立，
而且**我们当天正为它建了东西**（`scripts/watchdog.py`）。

每个循环 / 检测器（调度循环、对账、各种周期维护）：
① 要有**会随时间变旧**的活性痕迹（不是"我要不要干这个"的布尔标志）；
② 那个痕迹要**能被进程外的角色读到**。

⚠️ 为什么必须强调"进程外"：**我们所有的仪器都住在被观测的进程里** ——
进程自己装死时，那台仪器也在里面。防御模式 **§65 的规则 2 只到"进持久通道"，
没到"活性可观测"**，这一条补的就是后半句。
⚠️ **痕迹必须会变旧**：`/health` 报的 `_loop_running` 是个**布尔标志位**，
循环卡住它照样是 `true` —— 那种"活性"等于没有。

**怎么查**：列出所有循环 / 周期任务，逐个问 ——
① 它不动了，**盘上什么东西会变旧**？② 那个东西**谁在读**？读的人**在不在这个进程里**？

⚠️ **09-20 补（同一条咬了第二次）**：观察者自己的喇叭是空的 ——
`check_stalled()` 全仓**只有观察者自己和 admin 接口在用**，调度器一次都不调；
而它报警是广播给 `_pending_replies`，那个字典**几乎永远是空的**（唯一的注册入口全仓零调用者），
⇒ **没人聊天时，广播给一个空字典，无声消失，而且一个字都不落盘**。
🔵 **它要治的病和它得的病是同一个** —— 任务静默停滞没人知道／它静默失效没人知道，
"什么都不发生"与"一切正常"长得一模一样。**守护者的活性痕迹必须落在"它失效时你一定会看的地方"
（`alerts.jsonl` / 界面），不能只落在它自己的日志里。**

### 20. 状态与登记：要么原子，要么可回滚

**先改状态、后做事**这类顺序，中间断了就会留下一个**看起来在跑、其实没人管**的东西。
两个写法都行，**但不能都没有**：

- **原子**：状态变更和"登记"（future、句柄、索引）在**同一个不可分割的步骤**里完成；
- **可回滚 / 可兜底**：允许中间断，但**必须有人负责把半成品收掉**（且那个"有人"本身要满足第 19 条）。

**怎么查**：找所有"改了状态，接着还要做另一件事"的地方，问 ——
**中间断了，谁会发现？** 答"没人发现，它会一直挂着"就是没满足。

〔§65 先 transition(RUNNING) 再登记 future ⇒ 任务永远挂着、连 900s 收割都够不着〕
（实践：`orchestrator._strand_guard` 只管"收回"，**"原子"那一半还没有**）

### 37. 共享的句柄（模型 / 客户端 / GPU），并发使用前先确认它**线程安全**

"看着像纯函数"的推理调用最容易漏：共享的 MPS 模型被并发 `encode()` ⇒
**整个后端进程无声消失**（SIGSEGV，8 线程必崩、退出码 139），而且**加载那一句也是崩点**，
不只是推理。**不确定就当不安全，套锁**（加载 + 推理都要）。⚠️ 判它"并发安全"之前先问一句：
**这个假设是谁保证的？** 同族两个反面教材：跨线程改共享状态没守锁约定；
**RLock 同线程放行，挡不住重入** —— "加了锁"和"治好了"是两回事。

**怎么查**：列出所有"模块级 / 单例的句柄"（模型、HTTP client、连接池、GPU 上下文），
逐个问 —— **它线程安全吗？谁说的？** 说不出就加锁。

〔§74 共享的 MPS 模型被并发使用 ⇒ 整个后端进程无声消失 · §13 跨线程改共享状态没守锁约定〕

### 38. 原语在「空输入」下必须返回「空」，不能返回「当前状态」

`commit_wt` 对"没有改动"返回工作树的 HEAD —— 而工作树是从基线建的 ⇒ 返回的是**别人的提交**，
调用方**无条件**把它锚成"这个任务的产物"。**同一句话在不同调用方含义不同时，判据要放在调用方**
（`branch_ref != ctx.snapshot_ref`），不是改原语。
⚠️ 顺带一个更坏的陷阱：**"有没有未提交的改动"不能当"有没有产出"的判据** ——
agent 自己 `git commit` 过之后工作区是干净的，用它判会把**真的产出**当成没产出、**连合并都不做**。
**跟基线比才是对的。**

**怎么查**：每个"空输入 / 没变化"的分支问 —— **我返回的是"空"，还是"当时的现状"？**
调用方拿到这个值，会不会当成"有东西"？

〔§80 "没动过"被当成"有产物" —— 原语在空输入下返回了别人的东西〕

### 39. 生成物不许进版本库

`.pyc` 进了项目仓，代价在**三个地方分别出现，而且每次都像新 bug**：
① 多个任务碰同一模块 ⇒ 各自编译出不同二进制 ⇒ 合并必冲突；
② 跑测试会重新生成 pyc ⇒ "工作区必须干净"那条判据**在第①步就返回** ⇒ 状态来回打转；
③ **交付物被污染** —— `git archive` 导出的包里躺着 7 个 `.pyc`，一路漏到收件人手里。

**怎么查**：新项目 / 新目录问一句 —— **这里面哪些是生成物？它们被 gitignore 了吗？**
（建仓时就要写 `.gitignore` **并 `git add` 进初始提交** —— 只放文件不提交，等于没做。）

〔§77.6 `.pyc` 一个根因打了三枪（合并 / 判据 / 交付）〕

### 40. 和外部窗口共用一棵树时，不许替别人「定格」

`git add -A` 把**另一个窗口当时正在写**的半成品，扫进了 5 个不相关的提交 ⇒
那个窗口自己 `git status` 时看到的是 `M 已跟踪文件` 而不是 `?? 新文件` ——
**它按"没人动过"理解现场，而这个理解是错的**；`git blame` 从此指到那 5 条上，**来历丢了**。
**"这不是我的改动"不等于"它不重要"** —— 它可能只是还没写完，替他定格 = 替他做决定
（同族：删别人的东西前先留退路）。

**怎么查**：提交前先 `git status`，看到不认识的 `??` / `M` 先问"这是谁在写的"。
**共用一棵树时，提交必须写明确路径，不许 `git add -A` / `git commit -a`。**

〔§72 `git add -A` 把外部窗口正在写的半成品扫进了 5 个不相关的提交〕

### 41. 只读的操作，不许有副作用

`repo_dir()` 的兜底分支注释**明令"绝对不能 mkdir"**，而一个**只读**的调用点拿着它的返回值
`mkdir(parents=True)` ⇒ 盘上**只剩一个空目录**，而 `load()` 依旧返回 `None` ——
现场就成了"**空目录在、JSON 没了**"，看起来像**项目文件自己消失**。
四个调用点里**只有一个真要建**（而 `git worktree add` 自己会建父目录），另外三个是只读的 ——
**"绝对不许 X"那句话，没在调用点被尊重。**

**怎么查**：① 每个"读"类函数（`get` / `load` / `list` / `dir` 开头的），问它**会不会改盘上的东西**？
② 一个函数上写着"绝对不许 X"，去**列全调用方**，看有几处真遵守了。
③ 测试要钉**可观察的行为**（只读用法**没有**把目录建出来），别钉"调了哪个函数"。

〔§82.4 「绝不能 mkdir」的兜底路径，被只读的调用点 mk 出来了〕
