# 奇点已知问题 — 2026-07-02

## 🔴 致命：任务执行完成但状态不回写（reap bug）

**症状：** 任务 dispatched → API 调用执行完 → 心跳停止 → 任务状态停在 "running"，不转 done/failed。

**复现率：** 100%（连续 3 次 E2E 跑 blog 项目都卡住）

**定位范围：**
- 文件：`src/singularity/scheduler/orchestrator.py`
- 函数：`_run_queue_v3` → `_reap_futures`
- 模式：ThreadPoolExecutor(max_workers=2) + `wait(FIRST_COMPLETED, timeout=10)` + `fut.done()` 检测

**已尝试的修复（均未解决）：**
1. `batch.merge_request is not None` → `batch.merge_request` (truthy 判断，提交 c14278a)
2. reap 前先 `wait()` 再检查 done futures (提交 138c421)
3. deadline 从 600s 降到 300s + `fut.cancel()` (提交 138c421)
4. `_dispatch_ready` CAS 支持 BLOCKED 状态 (提交 c05af3f)

**关键代码位置：**
```
orchestrator.py:105-143  _reap_futures
orchestrator.py:209-228  _run_queue_v3 主循环
```

**可能方向：**
- ThreadPoolExecutor 在 daemon 线程中 future.done() 可能异步问题
- 考虑换成 ProcessPoolExecutor 或直接在线程里 .join()
- 考虑用 asyncio + create_task 替代 concurrent.futures
