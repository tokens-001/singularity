## 逐处详注（90580a2）

### 1. 人审门回复判定 `_is_gate_reply` —— 存疑

**修对的部分**：判定顺序改为先打回后批准，"不通过"不再被批准分支抢走（旧的批准在前、"不通过"含"通过"⇒ 打回永不生效，这个倒挂真实存在且已消除）；`reply is None` 落回普通聊天、不动门状态，无新竞态。

**没修够的部分**（① 部分达成 + ③ 同病残留两处）：
- 短词判据实现是 `len(bare) <= 4 and bare.startswith(w)`（`_observer_answer.py:50`），是**前缀**匹配不是注释声称的"整句就是它"。**"行不行？"**（去标点 3 字，startswith "行"）→ approved；**"可以吗"**（3 字，startswith "可以"）→ approved。这恰是 commit 自己举的反例"这方案行不行"去掉两个字——门照样被一句**疑问句**放过去。
- **"不同意"** 含"同意"子串（`_observer_answer.py:30`）→ approved；"不确认"、"别继续"同理。`_REJECT_WORDS`（:28）只收了"不通过"一个否定式，"先判打回"的排序哲学没落到词表上——架构门里用户回"不同意，这里有批漏"，门会把架构**确认**掉。
- 常量注释"允许 ≤4 字的后缀"（:31）与实现（前缀）自相矛盾，说明写的时候就没对齐。

证据：`src/singularity/scheduler/_observer_answer.py:28,30,31,32,35,50`；GATE1/2/3 三个调用点 ：164-230 行为一致（None 安全落空）。

### 2. `[::1]` → `::1` —— 对

`urlparse("http://[::1]:5050").hostname` 返回 `"::1"`（方括号被剥），旧 token 永不命中属实。两个调用点核实无副作用：CSRF 钩子（`app.py:267-270`，其中 remote_addr 白名单本来就认 `"::1"`，修的正是同一张表内的自相矛盾）；CORS 反射（`app.py:844`，只回显本机 Origin，浏览器不允许跨站伪造 Origin 头，无放宽风险）。备注：默认绑定是 `127.0.0.1`（`app.py:2306`），此坑只在改绑 `::`/反代时发作——修法仍正确。

证据：`src/singularity/web/app.py:776`。

### 12. 预算折成绝对时刻 —— 对

全链核实：orchestrator submit 前算 `deadline_at` → `TaskRunner.execute` 存入 `RunContext`（`_task_runner.py:202`）→ `_exec.py:556` 每次 dispatch 现算 `budget_s = deadline_at - now - 90s`（**排队时间在这里被自然扣掉**）→ `dispatch` 进门折成 `_budget_deadline`（:195）、fallback 链每轮重算 `(_budget_deadline - time.time())`（:223）。`None` 保持 `None`（阶段级路径不受影响）；负数放行属有意（执行器 `max(1.0,…)` 兜底），注释与实现一致。

### 13. 三执行器消费 budget_s —— 存疑（claude_cli 对，zhipu 对，anthropic 半成品）

- **claude_cli 对**：单子进程，`timeout=max(1.0, min(300, budget_s))`（`claude_cli.py:76-96`）即整次执行封顶=剩余预算，覆盖完整；超时路径的 error/elapsed 也同步用 `_tmo`。
- **zhipu 对**：重试循环每轮前查 `_deadline = start + budget_s`（`zhipu_api.py:56-70`），单次请求 timeout 同预算；退避睡眠可能一次越线但下一轮被 `_deadline` 拦住，有界。
- **anthropic 半成品**：`_tmo` 在**循环外算一次**（`anthropic_api.py:72-77`），当 `max_turns`（默认 **10**）轮**每一轮**的请求 timeout 用；循环体内**没有逐轮看表**——对照 openai_agent 的正确姿势 `if time.time() >= self._deadline_at: break`（`openai_agent.py:406`）。最坏 10×300s ≫ dispatch 预算；429 退避 `wait = 2 ** turn`（:103）也不受预算约束（turn 10 → 睡 1024s）。**声称要除的病（"照样越过任务死线被 900s 无声收割"）经 anthropic 路径仍然可达**——只是从"必现"降为"多轮才触发"。

### 14. 死线挪到 submit 之前 —— 对

全仓 `runner.execute` 调用点仅 `orchestrator.py:125` 一处，已传 `deadline_at`；收割起表 `running_futures[fut] = (…, time.time())`（:127）与 deadline_at 计算同刻（微秒差），"同一把尺同一个起点"成立；`deadline_at=0.0` 保底退回 worker 起算（测试/直接调用路径），`or` 判空对合法绝对时间戳无歧义。

### 15.（未登记）secret_key 读不动/空文件处理 —— 对（本体），流程上要点名

## 横向发现（按要紧程度排）

1. **anthropic-api 是三个"半修"的交汇点**：env 全量泄露（模块级 `_run_command` 没传 env，#4）、权限闸门缺席（`_execute_tool` 不调 checker，#5）、budget 只封单请求（无逐轮看表，#13）。同一执行器类型，三处声称修掉的病各剩一条活通道。若生产 agents.toml 里有 `type="anthropic-api"`，这三条的"已修"都要打折。
2. **"同一事实存两份"的两处结构性复发**：敏感文件黑名单（web 表 vs `base.py` 表，修一侧漏一侧，#3）与 MCP 配置文件 vs 注册表单例（修了 delete 漏了 add/update，#10）。建议各收敛成单一入口，否则下一轮还是这里。
