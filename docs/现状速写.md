## 一句话

AI Agent 调度平台：多模型按角色协作，把自然语言需求走完四阶段软件开发流水线（调研→架构→实现→审查），交付可运行的成品项目。**自部署、出厂零模型、数据落本地 JSON。**

| 引擎 | 位置 | 职责 |

| 知识引擎 | `data/knowledge/` | 句向量 + ChromaDB 语义搜索，任务进来先 pre_search 查可借鉴方案 |

## 流水线（`project.Phase` 共 12 个值）

```
template → 调研 → GATE1 → 架构 → GATE2 → 实现 → 集成 → 审查 →(修复) → GATE3 → 交付 → done
```

- **4 个"有模型产出"的核心阶段**：调研 / 架构 / 实现 / 审查（口头说的"四阶段"指这个）
- **3 个人工确认门**：GATE1（审调研报告）/ GATE2（审架构）/ GATE3（最终交付审核）
- 集成、审查、修复是**内部环节**，不是用户门；`修复` 是审查打回后的重做态
- 每道 GATE 有门禁审查，不通过打回重做

## 模型能力快照 + 推荐制

- `models.toml` 是能力快照：每个模型带 rating（SSS+~A 八档评级）+ recommended_for（推荐用途）+ strengths + cost + speed
- 调度按 recommended_for **权威推荐 + 用户自定义，不强制分层路由**（代码原文）
- **多模型委员会的触发条件是任务关键词，不是角色**：任务里出现
  「模块划分 / 数据模型 / API契约 / 技术栈 / 架构方案 / 系统架构」才走委员会
  （`_is_architecture_task`）。老文档写的「4 个关键角色多模型碰撞」已不成立。

## 核心数据流

```
用户 → Observer 对话 → 路由分类 → 流水线
     → dispatcher 分发 → executor 调模型 → validator GATE 审查
     → merge 合并 → 成品存 ~/qidian-projects/<项目名>
```

## 关键设计决策（现状）

1. **文件持久化零数据库**：`.qidian/` 下全 JSON，可 grep 排查。
2. **worktree 隔离**：每任务独立 git worktree，类 Docker 效果，git 原生零依赖。
3. **出厂零模型**：`models.toml`（能力快照，供调度器）vs `models_custom.json`（模型库，前端显示）。用户选厂家 → 输 key → 扫描导入。
4. **自部署**：Dockerfile + docker-compose，key 明文存项目 `.env`。
5. **执行器**：openai_agent / anthropic_api / claude_cli / zhipu_api 四个 runtime。
