## 四、文档里没写、但代码里有的重要规则

1. **静默 except 基线守卫**（tests/test_scheduler/test_no_silent_except.py + silent_except_baseline.json）：判据是「handler 体内含 `raise` 或调 witness/logging/log 才算出声」，`contextlib.suppress` 同罪；存量只按「顺手清」收敛不做批次，且**自报射程边界**（future 级吞噬不在射程）。防御模式 §48 只写了 F821 守卫，这台更大的守卫没写进去。
2. **机械检查的安全护栏**（_machine_checks.py）：argv 数组不过 shell、`argv[0]` 白名单（python3 只许紧跟 `-m pytest`）、`_clean_env` 洗掉 key/代理、cwd 锁项目仓、上限 10 条且超出明说（wfp:607-624）。防御 §21/性质 15 提了边界原则，这套具体白名单机制文档没有记录。
3. **告警键的纪律**（witness.py:38-49, 110-113）：`_derive_alert_key` **不认异常类名**（防把所有 KeyError 并成一条）；`alert_summary` 按 key 归并、**不带 scope**（同一常驻条件两个调用方各报时不劈成两行）。改告警措辞会劈开已有分组——这条约束只在代码注释里。
4. **心跳阈值与 deadline 联动**（witness.py:188-200）：`STALLED_AFTER_S = TASK_DEADLINE_S + 300`，理由是「阈值必须大于一次合法 dispatch 的上限」。改 `TASK_DEADLINE_S` 时这里会自动跟上（同一来源），但「为什么是这个形状」只活在注释里。
5. **调度不级联失败 + 降级可见**（tr:350-359 + wf:791-835）：上游挂了下游照跑（有意设计），但「这轮是降级跑的」会被 `_flag_degraded_tasks` 摆上 GATE3 人审页；配套还有 `_flag_file_overlap`（任务抢了兄弟任务点名的文件→进 issues，wf:726-788）。
6. **项目预算硬停**（wfp:125-157 + tb:439-457）：`token_budget_total` 的真实消费点——阶段开跑前查，80% 记告警、100% 停下等人工；探测失败**不拦**（预算探测不变成新卡点）。防御 §28 说它「声明了没兑现」是旧状，现在的兑现方式文档没记。
7. **GATE3 入门票**（proj:291-317）：进 GATE3 时没有 `verification_ran/verification_skipped` 记录就补 `gate3_no_evidence` + 告警——「验收整段没跑」在人审页上必然可见。配套 `arch_invalid` 不放行 GATE2（proj:180-188）。
8. **别名对账**（de:357-375 + oa:891-898）：厂商把旧模型名路由到新模型时，`api_store.record_alias` 在响应路径记账，委员会按「实际模型」去重、撞车时优先留「名字就是实际模型」的那个。这是对 §29「白名单写死精确版本」的实际解法，文档没记。
9. **熔断**（dispatcher.py:352-355 + `_model_breaker`）：刚连挂的模型本轮跳过；全池熔断时 fail-open 原样返回（否则一个坏 key 停摆整个调度），且 `error_kind="deadline"` 的收尾**不记 breaker**（de:225 注释：不是模型的锅）。

11. **repo_dir 兜底绝不 mkdir**（proj:350-361）：项目 JSON 没了时，目录兜底会造出「空目录在、文件没了」的假现场，所以宁可返回一个带告警的路径也不建目录。
