### 1.（并发/状态一致性）ProjectState「读→改→写」全程无锁，save() 的锁只护写盘一步
`project.py:471-489`（锁在 482，只包住 tmp 写+replace）；三个写者各自持快照：
- Flask 请求线程：`_api_tasks.py:503-506`，`task_submit` load → `task_ids.append` → save；
- 后台阶段线程：`_api_projects.py:273-291`，`_start_background` 起的 `run_phase`/`start_workflow` 持有**请求时装载的 proj 快照**分钟级运行并随时 save；
- 调度循环线程：`app.py:569-602` 把 `recover_all()` 的 proj 交给 `run_test_fix_loop`。

后保存者把先保存者的整份修改盖掉。最实的后果：任务 id 从 `project.task_ids` 消失，而 orchestrator 只认 `task_ids`（`_api_tasks.py:500-501` 注释自证）→ 该任务永远不会被调度，界面上"任务在、项目不带它"。

**怎么验**：项目 P 存在时 `curl -X POST :5050/api/tasks -d '{"description":"a","project_id":"P"}' & curl -X POST :5050/api/tasks -d '{"description":"b","project_id":"P"}' & wait`，重复若干次：tasks_dir 里两个任务都在，但 P.json 的 `task_ids` 只有 1 个。更稳的复现：planning 后台线程运行期间（分钟级窗口）提交任务，阶段结束后看该任务是否还挂在 task_ids 里。

### 2.（并发/可用性）SSE 断线重连回放：迭代 deque 时别线程 append → RuntimeError，重连即死
`app.py:2076-2078`，`for eid, data in _sse_event_buffer:` —— `_sse_event_buffer` 是 deque，被 `_sse_broadcast`（泵线程/循环线程/请求线程都会调，app.py:692）随时 append。CPython deque 迭代中一旦被变更即抛 `RuntimeError: deque mutated during iteration`；回放块外面没有 try/except（`init` 块 2084-2093 有，回放没有）→ 生成器直接死 → 这条重连连接立即断开无任何数据。触发面正好是"面板已经断了在重连"的时刻，事件越繁忙概率越高。

**怎么验**：单元级：线程 A `for x in d:`，线程 B 不停 `d.append(x)`，即见 RuntimeError。端到端：让任务跑着（事件流不断），反复 `curl -N -H "Last-Event-ID: 1" http://127.0.0.1:5050/api/events`，偶发"连上即断、零输出"。

### 3.（状态不一致/资源泄漏）MCP 删除/改配置不动 registry：删了的服务器还连着、工具还在
`_api_admin.py:440-442` `mcp_server_delete` 只改配置文件；`reg._clients` / `reg._tools` / `reg._tool_index` 原样保留（对比同文件 `mcp_server_reconnect` 445-453 是清理干净的）；app.py:2146-2151 的 DELETE 路由只 invalidate 调度缓存。结果：已删除服务器的子进程还活着、`/api/mcp/tools` 里工具还在、agent 还能继续调到。同病：`mcp_server_add` 的更新分支 `_api_admin.py:427-432` 改了 command/url 也不重启旧 client，跑的还是旧命令。

**怎么验**：加一个 `command:"/usr/bin/tail -f /dev/null"` 的 stdio server → 等它 connected → `DELETE /api/mcp/servers/<name>` → `GET /api/mcp/servers` 仍 `connected:true`，`GET /api/mcp/tools` 工具还在，`ps` 里 tail 未退。

### 4.（安全/信息泄露）`/api/auth/status` 在免认证白名单里，未认证可拿全量用户清单

### 5.（安全/边界）项目文件读取接口的敏感文件黑名单漏 `.env.local` / `id_rsa` 一类
