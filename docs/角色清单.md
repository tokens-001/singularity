# 角色清单与现状（2026-09-10）

## 目标形态

**角色 = 一段约束提示词，绑定研发阶段**（不是绑定模型 —— 那是错的维度：
模型回答"谁来做"，角色回答"做什么、不做什么"）。

一个角色可用于多个阶段，一个阶段只用一个角色 → **一对多映射**，所以映射表单独放，
不塞进角色定义里。

## 搬迁的拆法（关键）

`_RESEARCHER_PREAMBLE` / `_ARCHITECT_PREAMBLE` 不是纯文本，混了三类东西：

```
你是项目调研员。基于项目需求，完成六维度调研报告。   ← 静态：角色定位 → 搬进角色
项目需求: {description}                              ← 动态：上下文   → 留代码
1. 竞品分析 … 6. 约束识别                            ← 静态：维度清单 → 搬进角色
输出格式 (JSON，```json 包裹): {{...}}               ← 静态：输出契约 → 留代码（代码要解析它）
你只做调研，不写代码。                                ← 静态：边界     → 搬进角色
```

**角色提示词只收"静态约束"，动态上下文和输出 schema 留在代码** ——
否则编辑页得教用户写 `{description}`。

## 阶段映射（已落地）

```python
# roles._DEFAULT_PHASE_ROLES —— 可在 .qidian/phases.json 覆盖
{
  "researching": "surveyor",
  "planning":    "architect",
  "executing":   "implementer",
  "fixing":      "implementer",
  "reviewing":   "reviewer",
}
```

QA 验收 / 安全审计是 REVIEWING 里**并列的两次独立调用**（不是主审查角色），
所以它们不占映射位，仍由 validator 直接取。
