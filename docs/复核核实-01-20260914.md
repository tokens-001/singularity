## 条1：手动取消运行中的任务后，它会重新跑 —— **成立**

**后果**：用户点取消后，取消意图只活在一个马上会被删掉的标记文件里；worker 把这次中断当普通失败重试（还先 rollback 到快照基线），任务最多重新跑 3 轮、继续烧 token，且 tracker 状态全程停在 RUNNING，直到重试耗尽才 FAILED。

**证据链（三环都实锤）**：
1. 取消接口对 RUNNING/DISPATCHED/PAUSED **只写标记文件、不 transition 状态**：`_api_tasks.py:283-290`（写 `config.CANCEL_DIR/{task_id}.json` 后直接 return "已发送取消信号"；只有 PENDING/ROUTED 等非运行态才走 292 行的 `transition(FAILED)`）。
2. 执行线程查到标记后**先删标记再返回**：`_exec.py:260-266` —— `_check_cancelled` 第 262 行 `cancel_path.unlink()`，然后返回 `ok=False, term_reason="cancelled_by_user"`。
3. 外层重试循环 `_run_with_retry`（`_exec.py:771-819`）的早退判据只有三条：`batch.ok or planner_decomposed`（794）、`term_reason.startswith(("merge_conflict","soft_quality_gate"))`（796）、`deadline_wrapup`（798）。**`"cancelled_by_user"` 三条全不中** ⇒ 走到 803 行 `retry += 1`，`task.max_retries` 默认 3（`tracker.py:76`）⇒ 回到 780 行重新调 `run()`；而标记在第 262 行已被删 ⇒ 新一轮 `run()` 里 `_check_cancelled` 返回 None（`_exec.py:272`），任务照常执行。

## 条2：人审门两处假放行 —— **两条都成立**

## 条3：env 脱敏只修了类方法那份，anthropic 执行器走没脱敏的模块级函数 —— **成立**

**后果**：AnthropicApiExecutor 的模型调 `run_command` 工具时，子进程继承**未脱敏**的完整 `os.environ` —— `ANTHROPIC_API_KEY` / `OPENAI_API_KEY` 等所有敏感变量随口一条 `env` 命令就能读走；而同一仓库里 openai 执行器同工具是脱敏的，防线对一半。

**证据**：
- 修好的那份（类方法）：`openai_agent.py:790-802` —— `_tool_run` 里 `merged = {**os.environ, **self._agent_env}` → `safe_env = {k: v ... if not _is_sensitive_env(k)}`（797-798）→ `subprocess.run(..., env=safe_env)`（802）。头部注释 37 行明说意图："模型跑 `run_command` 时，`os.environ` 要脱敏后再给"。
- 没修的那份（模块级）：`openai_agent.py:1137-1153` `_run_command(args, cwd)` —— 1148 行 `subprocess.run(argv, shell=False, capture_output=True, text=True, timeout=30, cwd=str(cwd))`，**没有 `env=` 参数** ⇒ 子进程继承全量 `os.environ`。
- 走到没修那份的执行器：`anthropic_api.py:194-196` 从 openai_agent **import 模块级 `_run_command`**，`:205-206` 把 `run_command` 工具直接派给它。openai 执行器自己则走 `self._tool_run`（`openai_agent.py:716-717`），所以全仓库只有 anthropic 执行器的 `run_command` 不脱敏（grep 全 executors 目录仅此一处 import）。
