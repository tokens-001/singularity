## 读码撞见的顺带发现（不属 51 条，建议立账）

1. **清单 #45 的 secret_key 子条已过期**：清单写"要改成『不覆盖+出声+内存随机』（还没改）"——现在代码**已经是那个形状**（app.py:74-87：OSError→不覆盖、`secret_key_unreadable` 告警、进程内随机 key；空文件→`secret_key_empty_file_used_ephemeral`）。待办可以销了。
2. **清单 #33 的"并发 1"按实际部署不成立**：`run_queue` 默认 1 没错，但 web 启动自自动 `start_loop(concurrent=2)`（app.py:2295）。"一个暂停任务占死整个队列"只在并发=1 或两个都暂停时发生。
3. **#42 判据①可能落空**：`_soloN` tag 静态上看不到任何落盘出口（不进 trace、不进账本；账本按 member_usage 记的是模型名+token）。真机跑 A 臂前先把"从哪观测到 solo 轮"定了，否则白跑。
4. **疑似真洞：取消/被收割的任务会被重试再烧钱**。链路已全程闭合：
   - 手动取消对 RUNNING/PAUSED 任务**只写取消标记、不转状态**（_api_tasks.py:283-290）；
   - 执行线程在下一个 turn 边界看到标记 → **unlink 掉** → 返回 `term_reason="cancelled_by_user"` 的失败 BatchOutput（_exec.py:258-272）；暂停中被取消同理（暂停循环查的就是 CANCEL_DIR，_exec.py:299-304，恢复路径返回 `cancelled_during_pause`）；
   - 而 `_run_with_retry` 的早退集合只有 `merge_conflict / soft_quality_gate / deadline_wrapup`（_exec.py:796-801），**两个取消 term_reason 都不在**，`deadline_wrapup` 也未置位 ⇒ `retry += 1` 再进 `run()`；
   - 此时标记已被删，`_check_cancelled` 拦不住，`run()` 重读任务也**不检查状态**（_exec.py:447-449）⇒ **真金白银再 dispatch**，最多再来 3 次（max_retries=3）；且 future 早在收割/返回路径上被消费，重跑结果没人接。
