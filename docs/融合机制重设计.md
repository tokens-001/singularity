## 一、目标与判据

**目标**：多模型各出方案 → 得到一份**优于任何单份输入**的共识方案。

**判据（用户定，比"vs 外部参照"可信）**：

```
融合 ≥ max(输入方案)          ← 理论上必然，不满足 = 机制或实现有问题
融合 尽量接近高一档模型        ← 不强制，但应"无限接近"
```

用这个判据而不是"vs 外部参照"，因为参照自身波动极大（实测 glm-5.3 在
同一裁判下 23↔48 跳 25 分）。

## 二、现状机制与三个缺口

现状：`_dispatch_exec._dispatch_committee` → `_debate`（整份方案互评 2 轮 × 2 波）
→ `execution_judge.fuse_architecture`（阶段一五维分析 + 阶段二重写全文）。

| 缺口 | 表现 | 后果 |
|---|---|---|
| **1. 没有"反驳"通道** | 修订提示词只说"吸收合理意见" | 审核方的**误判被当真吸收** → 把缺陷结合起来 |
| **2. 取并集 → 输出膨胀** | 规则只有"加"（consensus 锁定 + unique 补充 + blind_spots 补缺），没有"删" | 输出 ≈ 输入之和（实测 24k~28k 字，单稿的 1.8 倍）→ 撞 max_tokens 被腰斩 |
| **3. 分歧靠裁判单方裁决** | 阶段一直接给 `winner` | 裁判与选手同档，裁得对不对没保障 |

**缺口 2 已造成实际事故**：三题融合稿全部被 `max_tokens=16000` 腰斩，
brief 3 因此丢了整个 `tasks` 段（schema 必填）→ 评审该维度 0 分 → 误判为"融合无收益"。

## 三、新机制规格

```
① 各出方案（N 份，并行）                                  ← 现有，不改

② 提取三类（1 次调用）
   {
     consensus:    ["已一致的点"],                        ← 只列点，不展开
     disagreements:[{id, 维度, 分歧点, 各方立场, 提出方}],
     unique_gains: [{id, 内容, 来自哪家, 影响面}]         ← 某家独有、别人没有
   }

③ 共享对话（交替往复，`QIDIAN_FUSION_V2_ROUNDS` 上限默认 5）
   轮1（提出分歧较多的一方）：对**全部分歧点**逐条陈述己方理由
   轮2（另一方）：逐条回应
        accept     = 被说服，采用对方观点
        insist     = 坚持 + **解释为什么对方误判**
   轮3（回到轮1方，仅当有 insist 时）：对 insist 的条目确认 —— 认可 / 继续质疑
   轮4/5：仍有 question 才继续（对方再回应 → 发言方再确认）
   终止：全 accept / 发言方全 agree（**有人让步才算结论**）/ 复读（本轮与上轮结论相同）/ 撞上限

   上下文：需求 + 各方案 + 已有对话
   约束：只谈清单上的条目，不许重述方案；每轮输出结构化
   终止：所有条目有结论（**几乎不出现折中** —— 用户实测经验）

   unique_gains 在 ③ 里一并表态：采纳 / 不采纳（+理由）
   不一致的按分歧同样处理

④ 定稿（2 次调用）
   最后发言方成文 → 另一方确认（不认可则回 ③）
   输入是**对话结论**，不是 N 份方案全文      ← 关键：从根上控制长度
```

### 为什么这样设计

- **`insist + 解释` 是防误判的闸** —— 补上现状最缺的"反驳"通道。
- **收敛靠"谁改了立场"读出来** —— 不需要裁判，避开"裁判同档"问题。
- **长度从机制上解决**：共识点不增加、分歧点二选一、只补 blind_spots → 输出 ≈ 单份方案。
- **成本不涨反降**：② 1 + ③ 2-3 + ④ 2 = 5-6 次（现在 7 波）。

## 四、已定的设计决定

| 问题 | 决定 |
|---|---|
| 发言顺序 | 每个分歧点由**提出方**先说 |
| 轮数上限 | `QIDIAN_FUSION_V2_ROUNDS`，默认 **5**（理想 2 轮定稿；只有双方死扛才跑到 4/5） |
| 收敛判据 | **有人让步**（accept/agree）才算结论。`question` 不终局 —— 否则加轮数就是加死代码 |
| 折中 | 几乎不出现，机制里不设 `compromise` 档 |
| 定稿 | **最后发言方**成文，另一方确认 |
| unique_gains | 在对话里一并表态，有取舍（不是全都要） |
| 采纳门槛 | **全体 adopt 才采纳**（有人 reject 就不加）—— 长度就是膨胀主因，宁少勿滥 |
| 分歧归谁 | 默认发言方胜；对方 insist 且发言方 `agree`（认输）→ 对方胜；`question` → 发言方胜 |
| 确认不通过 | 带 issues 重写 **1 次**，仍不通过就采用（不回 ③，避免成本失控） |
| N>2 的歧义 | 多个 insist 方立场不同时只记第一个 —— 分歧点几乎都是两家对立 |

## 五、实现要点

**改哪里**（✅ 已完成）：

**必须遵守**（✅ 已遵守）：

  `""` 回退旧流程，不会拿垃圾定稿

**测试**：

## 六、验收标准

```
跑 1 题 → 看「融合 vs 它自己的输入」
  融合 ≥ max(输入)  → 机制对了
  融合 <  max(输入)  → 有 bug，回去查（先查是不是又被截断）
```

**不要**再用"vs 外部参照"当主判据（参照波动太大）。

## 七、未定 / 待验证

1. **模型会诚实 accept/insist 吗？** 已知风险：谄媚性顺从（谁后说听谁的）或
   固执己见（什么都 insist）。**这是整个机制的前提，未测 —— 实现后第一个该验的。**
2. ~~对话上下文放不放方案全文？~~ → **放**。③ 每轮都带各方案全文，受单份
   `QIDIAN_FUSION_PLAN_CHARS`（20000）+ 合计 `QIDIAN_FUSION_PLANS_TOTAL`（60000，按 N 均分）
   双重限制；④ 定稿只吃对话结论，不吃全文。
   实测（2 家真实方案）：轮 1/2/4 约 31-36k 字，**轮 3/5 确认只 4-9.5k 字**（不带方案），
   定稿 2.6k 字。对话记录每轮只涨 ~2.7k 字，5 轮上限 ≈ 11k 字 —— 不会爆。
3. ~~分歧数相当时谁先发言？~~ → 取 `members` 顺序靠前者（`_first_speaker`）。
4. ~~定稿方若是 insist 方会不会偏向自己？~~ → 定稿方 = **轮 1 发言方**（提出分歧最多的一方），
   不是"最后发言方"。理由：轮 2 是并行多路，N≥3 时没有单一"最后发言方"；轮 1 方听完了
   所有回应，掌握全部立场。偏向风险由 ④ 的确认步骤兜。
5. 机制性膨胀是否真的消失（新机制输出应 ≈ 单稿 1.1-1.3 倍，待实测）
