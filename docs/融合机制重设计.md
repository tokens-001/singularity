## 一、目标与判据

**目标**：多模型各出方案 → 得到一份**优于任何单份输入**的共识方案。

**判据（用户定，比"vs 外部参照"可信）**：

```
融合 ≥ max(输入方案)          ← 理论上必然，不满足 = 机制或实现有问题
融合 尽量接近高一档模型        ← 不强制，但应"无限接近"
```

用这个判据而不是"vs 外部参照"，因为参照自身波动极大（实测 glm-5.3 在
同一裁判下 23↔48 跳 25 分）。

## 二、现状机制与三个缺口

现状：`_dispatch_exec._dispatch_committee` → `_debate`（整份方案互评 2 轮 × 2 波）
→ `execution_judge.fuse_architecture`（阶段一五维分析 + 阶段二重写全文）。

| 缺口 | 表现 | 后果 |
|---|---|---|
| **1. 没有"反驳"通道** | 修订提示词只说"吸收合理意见" | 审核方的**误判被当真吸收** → 把缺陷结合起来 |
| **2. 取并集 → 输出膨胀** | 规则只有"加"（consensus 锁定 + unique 补充 + blind_spots 补缺），没有"删" | 输出 ≈ 输入之和（实测 24k~28k 字，单稿的 1.8 倍）→ 撞 max_tokens 被腰斩 |
| **3. 分歧靠裁判单方裁决** | 阶段一直接给 `winner` | 裁判与选手同档，裁得对不对没保障 |

**缺口 2 已造成实际事故**：三题融合稿全部被 `max_tokens=16000` 腰斩，
brief 3 因此丢了整个 `tasks` 段（schema 必填）→ 评审该维度 0 分 → 误判为"融合无收益"。

## 三、新机制规格

```
① 各出方案（N 份，并行）                                  ← 现有，不改

② 提取三类（1 次调用）
   {
     consensus:    ["已一致的点"],                        ← 只列点，不展开
     disagreements:[{id, 维度, 分歧点, 各方立场, 提出方}],
     unique_gains: [{id, 内容, 来自哪家, 影响面}]         ← 某家独有、别人没有
   }

③ 共享对话（交替往复，`QIDIAN_FUSION_V2_ROUNDS` 上限默认 5）
   轮1（提出分歧较多的一方）：对**全部分歧点**逐条陈述己方理由
   轮2（另一方）：逐条回应
        accept     = 被说服，采用对方观点
        insist     = 坚持 + **解释为什么对方误判**
   轮3（回到轮1方，仅当有 insist 时）：对 insist 的条目确认 —— 认可 / 继续质疑
   轮4/5：仍有 question 才继续（对方再回应 → 发言方再确认）
   终止：全 accept / 发言方全 agree（**有人让步才算结论**）/ 复读（本轮与上轮结论相同）/ 撞上限

   上下文：需求 + 各方案 + 已有对话
   约束：只谈清单上的条目，不许重述方案；每轮输出结构化
   终止：所有条目有结论（**几乎不出现折中** —— 用户实测经验）

   unique_gains 在 ③ 里一并表态：采纳 / 不采纳（+理由）
   不一致的按分歧同样处理

④ 定稿（2 次调用）
   最后发言方成文 → 另一方确认（不认可则回 ③）
   输入是**对话结论**，不是 N 份方案全文      ← 关键：从根上控制长度
```

### 为什么这样设计

- **`insist + 解释` 是防误判的闸** —— 补上现状最缺的"反驳"通道。
- **收敛靠"谁改了立场"读出来** —— 不需要裁判，避开"裁判同档"问题。
- **长度从机制上解决**：共识点不增加、分歧点二选一、只补 blind_spots → 输出 ≈ 单份方案。
- **成本不涨反降**：② 1 + ③ 2-3 + ④ 2 = 5-6 次（现在 7 波）。

## 四、已定的设计决定

| 问题 | 决定 |
|---|---|
| 发言顺序 | 每个分歧点由**提出方**先说 |
| 轮数上限 | `QIDIAN_FUSION_V2_ROUNDS`，默认 **5**（理想 2 轮定稿；只有双方死扛才跑到 4/5） |
| 收敛判据 | **有人让步**（accept/agree）才算结论。`question` 不终局 —— 否则加轮数就是加死代码 |
| 折中 | 几乎不出现，机制里不设 `compromise` 档 |
| 定稿 | **最后发言方**成文，另一方确认 |
| unique_gains | 在对话里一并表态，有取舍（不是全都要） |
| 采纳门槛 | **全体 adopt 才采纳**（有人 reject 就不加）—— 长度就是膨胀主因，宁少勿滥 |
| 分歧归谁 | 默认发言方胜；对方 insist 且发言方 `agree`（认输）→ 对方胜；`question` → 发言方胜 |
| 确认不通过 | 带 issues 重写 **1 次**，仍不通过就采用（不回 ③，避免成本失控） |
| N>2 的歧义 | 多个 insist 方立场不同时只记第一个 —— 分歧点几乎都是两家对立 |

## 六、验收标准

## 七、未定 / 待验证

1. **模型会诚实 accept/insist 吗？** 已知风险：谄媚性顺从（谁后说听谁的）或
   固执己见（什么都 insist）。**初步标定通过**（见第八节，4/4，样本小）。
   但实跑里出现「先说的一方 3:0 全胜」——**样本不足以排除偏向，继续盯。**
2. ~~对话上下文放不放方案全文？~~ → **放**。③ 每轮都带各方案全文，受单份
   `QIDIAN_FUSION_PLAN_CHARS`（20000）+ 合计 `QIDIAN_FUSION_PLANS_TOTAL`（60000，按 N 均分）
   双重限制；④ 定稿只吃对话结论，不吃全文。
   实测（2 家真实方案）：轮 1/2/4 约 31-36k 字，**轮 3/5 确认只 4-9.5k 字**（不带方案），
   定稿 2.6k 字。对话记录每轮只涨 ~2.7k 字，5 轮上限 ≈ 11k 字 —— 不会爆。
3. ~~分歧数相当时谁先发言？~~ → 取 `members` 顺序靠前者（`_first_speaker`）。
4. ~~定稿方若是 insist 方会不会偏向自己？~~ → 定稿方 = **轮 1 发言方**（提出分歧最多的一方），
   不是"最后发言方"。理由：轮 2 是并行多路，N≥3 时没有单一"最后发言方"；轮 1 方听完了
   所有回应，掌握全部立场。偏向风险由 ④ 的确认步骤兜。
5. ~~机制性膨胀是否真的消失~~ → **消失**（实测 0.91×，甚至比单稿短）。但代价是丢了
   `tasks`/`risks` —— 见第八节，待定 ④ 要不要补原文。

## 八、2026-09-10 首次实跑（brief 3，glm-5.2 + deepseek-v4-pro）

**跑通了**，5 次调用（旧机制 6 波）：

| 步 | 模型 | 结果 |
|---|---|---|
| ② 提取 | glm-5.3-flash | 3636 字，2 条真分歧（金额精度 / 用量存储链路） |
| ③ 轮1 陈述 | deepseek-v4-pro | 2442 字 |
| ③ 回应 | glm-5.2 | 3 条全 accept，理由具体（举出 GB-hours、0.0003 元/次 反例） |
| ③ 确认 | — | 跳过（全 accept → 收敛，符合设计） |
| ④ 定稿 | deepseek-v4-pro | 13930 字 |
| ④ 确认 | glm-5.2 | **空返回**（已加 `warn:fusion_confirm_empty`） |

**膨胀解决了**：13930 字 / 单稿最长 15234 = **0.91×**（旧机制 1.8×）。

**但丢了 `tasks` / `risks`**（schema 必填）—— **不是截断**。真原因：④ 的输入只有
4953 字的对话结论、**没有原文**，写手没有材料可写这些段落。**这是设计张力**：
「定稿只吃对话结论」是压长度的关键，代价是只能写出结论里有的东西。

**待定**：④ 要不要补原文（补 → 长度回来；不补 → 缺段落）。

### 顺带修的两个真 bug（都不是 v2 独有）

1. `_call_model` 不认 `reasoning_content`（执行器 `openai_agent.py:406` 认）→
   **任何思考模型走融合路径都静默返回空**，旧路径的 stage1/stage2 同样中招。
   已修：模型正常收尾（finish≠length）时回退 reasoning_content；撞 `length` 不回退
   （那是半截思考不是答案）。
2. `deepseek-v4-flash` 注册表标 `reasoning = false`，实测会输出思考链 → **标错了**。

### accept/insist 标定（`tests/integration/calib_accept_insist.py`）

喂「误判」（方案明明做了，对方说没做）和「真缺口」各一条，看回应准不准。
4 条全对：两条误判都 insist 并**引用方案原文**指出对方误判；两条真缺口都 accept。
样本小（2 模型 × 2 条），但**没有谄媚或硬扛的迹象**。

## 十、2026-09-10 收尾：两个根因（**下次从这里接**）

### 1. 测试喂的输入 ≠ 生产喂的输入（已修 `538157e`）

测试脚本喂裸 brief（一行需求、无 schema），生产喂
`roles.toml [architect]` 提示词 + 需求 + **完整 schema**（约 2k 字）。
模型因此各写各的格式 —— 缓存实测：v4-pro 输出的是数据模型
（`task_id,queue,payload`）、glm-5.2 自创 `System_Name,Module_Partitioning`、
brief 2/3 两份都解析不出来。融合被迫做格式翻译，**第二节记的 1.8× 膨胀多半就是这么来的**。

已修：`ab_fusion.arch_task()` 造生产形态任务；`v2_fusion_run.py` 默认现跑委员会
（初稿缓存 `.v2_plans.json`）；融合需求截断 1500 → `QIDIAN_FUSION_TASK_CHARS`(4000)；
模板字段重排（生产 + 融合 schema 同步）：tasks/risks 从末尾挪到 modules 之后。

### 2. 同一个模型两条路，行为不一致（**未修 ← 下次从这里接**）

```
初稿     走执行器 _run_no_tools   max_tokens=20000  认得 reasoning_content   ✓ 5992 字
v2 对话  走 _call_model          max_tokens=6000/16000  不认                 ✗ 0 字
```

实测（brief 3，生产形态任务，3 席）：

```
② 提取三类   glm-5.3-flash            → 2751 字 ✓
③ 轮1 陈述   deepseek-v4-flash        →    0 字 ✗
③ 回应       kimi-k2.7-code-highspeed →    0 字 ✗（限流）
③ 回应       glm-5.3-flash            → 1768 字 ✓
④ 定稿       deepseek-v4-flash        →    0 字 ✗ → 整条返回空
```

根因：委员会里的思考模型在 `_call_model` 上把预算全烧在思考上，
`finish_reason=length`、content 为空。**全仓库没有任何"关闭思考"的参数，关不掉**，
只能给够预算（执行器给 20000 就能出稿）。

**下一步**：把 v2 的**成员调用**改走执行器（`_run_no_tools`，需把 `chain`
传进 `fuse_architecture_v2`）。提取模型是外部非思考模型，继续走 `_call_model` 即可。

改完重跑一次，就能拿到那个一直没拿到的数：**融合 ≥ max(自己最好的输入)？**

# 十一、2026-09-10 续：额度是真凶（本轮结账）

## 根因确认

v2 跑不完不是机制问题，是**输出额度**：成员调用走 `_call_model`（6000/4000/2000），
初稿走执行器（20000）。思考模型把额度烧在 reasoning 上 → `content` 空。
**给足额度后 6 次调用全部有回复。**

## 改了哪些数

| 位置 | 原来 | 现在 |
|---|---|---|
| `config.MODEL_MAX_TOKENS`（新增） | — | **131072**（env `QIDIAN_MODEL_MAX_TOKENS`） |
| 初稿 `request_template` ×2 | 20000 | 131072 |
| `_FUSION_MAX_TOKENS` | 16000 | 131072 |
| v2 对话/确认 ×4 | 6000/4000/2000 | 131072 |
| `_V2_EXTRACT_MAX_TOKENS` | 16000 | 131072 |
| 旧机制 stage1 | 4000 | 131072 |
| `_FUSION_PLAN_CHARS` | 20000 | **40000** |
| `_FUSION_PLANS_TOTAL` | 60000 | **120000** |

**额度是保险丝不是油门**：实测 trivial 任务给 20000 只烧 41；30 万字输入 +
`max_tokens=393216` 仍返回 200。端点自报上限：智谱 `[1,131072]`、DeepSeek `[1,393216]`
→ 取最紧的 **131072**（也是国产顶级模型的公共天花板：Kimi/MiniMax/Qwen 默认或上限均落在此）。

## 实测数字（brief 3，glm-5.3-flash + deepseek-v4-flash）

| | 对照残废那次 | **对照完整这次** |
|---|---|---|
| 单稿 | 11480 / 16640（截断） | **23713 / 31347**（完整） |
| 融合稿 | 34483 | 30869（tasks ✓ risks ✓） |
| 打分 | 28 / 30 / 48 | 43 / 45 / **48** |
| 差 | +18 | **+3** |
| 长度 | 2.07× | **0.98×** |

- **+3 落在评委噪声（±3）边缘 —— 等于"看不出差别"。** 融合稿两次都是 48，很稳；

- 教训重演：**对照被截断会把结论推向反面**，这次是推向正面。两次都是同一个坑。
