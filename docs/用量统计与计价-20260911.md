# 用量统计与计价（2026-09-11）

> 起因：用户说「现在是总量统计，没意义，应该是按模型统计用量，因为模型收费标准也不一样」。

## 一、诊断：用量早就按模型统计了，**钱是编的**

`_token_budget._estimate_cost` 写死一张 8 模型价目表 + `rates.get(model, 0.50)` **静默兜底**。
用户实际在用的 `deepseek-v4-flash` 不在表里 → 按假的 $0.50/百万 算。
验算 `375188 ÷ 100万 × 0.50 = 0.187594`，与界面显示分毫不差。

全仓**没有任何真实价格数据**：`api_store.json` 无价格；`_guess_cost()` 返回的是
`budget/standard/premium` 档位字串，且该档位**全仓没有一处拿去算钱**。

顺带查出**另外 4 处同类编造**：

| # | 位置 | 编造方式 |
|---|---|---|
| 1 | `_token_budget._estimate_cost` | 8 模型写死表 + 静默 `0.50` 兜底（界面上的钱） |
| 2 | `_planner.py` `COST_PER_M` / `est_cost_usd` | 注释自认「混合均价 ~$0.5/M」 |
| 3 | `_cli_projects._phase_cost_estimate` | 又一张表，显示为「估算费用 ~$2.50」 |
| 4 | `_api_projects.project_cost` | 同一张表的副本 |
| 5 | `proj.token_spent` | **全仓无赋值处**，恒 `$0.00`；连带「⚠ 预算将超支」是死代码 |

前端还有 `(x \|\| 0).toFixed(2)` 三处，把缺失值渲染成看着可信的 `$0.00`。

## 二、两个关键设计决定

### 1. 单价存**独立文件**，不塞进 `ModelEntry`

`.qidian/model_prices.json` + `scheduler/model_prices.py`。

理由（已核实）：`_benchmark.py` 与 `models_import` 会把模型条目**整行重建**
（每个字段重新传一遍）。价格存行里 = 点一次「跑基准」或做一次「扫描导入」就**静默归零**。
分开存让这种失败**结构上不可能**。有测试锁住（`add_model` / `save_custom_model` 两个形状跑完价格仍在）。

`price_for()` **绝不兜底** —— 那里就是旧 `rates.get(model, 0.50)` 的坟。

### 2. 费用**读时现算**，不写盘时算

`record()` 不再算钱。好处：**不需要迁移脚本/回填/手改 JSON**，旧假值随上线直接消失，
而且**用户填上单价的瞬间历史用量自动变对**。

⚠️ **`UsageRecord.cost_est` 字段必须保留**（现在只是"不再读写的遗留列"）：
`_load()` 走 `UsageRecord(**r)`，删掉它会让历史行抛 `TypeError` 被 `except` 吞掉
→ **整份用量历史静默消失**。有测试守着。

## 三、统计只覆盖了 1/6 的调用

用户问「统计不应该全流程的用量都统计吗」—— 对。全仓 6 条调用大模型的路，
**只有"派任务去干活"那条记账**：

| 路 | 状态 |
|---|---|
| `_task_runner` → dispatch → 执行器 | 本来就有 |
| `_observer_answer`（观察者对话，2 处） | 补。接口早返回 `usage`，代码只取 content 把它丢了 |
| `router.py`（**任务分类，每建一个任务都调**） | 补 |
| `execution_judge._stream_once`（**架构融合，单次最贵**） | 补。**流式默认不带 usage**，要申请 `stream_options.include_usage` 才拿得到 |
| `_memory_consolidator` | 补 |
| `goal_loop` | 补 |

统一走 `record_system_tokens(model, level, tokens)`，`level` ∈
{observer, router, fusion, memory, goal} → `by_level` 能按用途拆开看。

## 四、按天历史（`usage_daily.json`）

存**按天聚合的桶**（不是原始行）：`{tokens, tasks, elapsed_s, max_elapsed_s, models, hours[24]}`。

**折叠算法是本模块最关键的处**：`_daily` 是最近两天的原始行、**不按天过滤**。
若只重算 `days[今天]`，每天 00:01 的第一条记录会把昨天那批行一起算进今天
→ **每过午夜重复计一次**。正确做法是**每条记录归到它自己那天**，再按分量取 max 合并。

max 成立的前提：桶里每个字段对行集合**单调不减**。⚠️ 谁要加"平均""最大间隔"这类
非单调字段，max 合并立刻就是错的。

保留最近 400 天。截断必须说：接口返 `earliest`，页面标注「统计自 X」。

## 五、模型"只有一个在干活" —— 是设计，加了轮换又撤掉

`any` 层那个模型列表**本质是"主力 + 备用"**，原设计就是永远用第一个、挂了才用下一个。
调用方永远取链首，所以配了 7 个也只有第一个跑 —— **不是 bug**。

一度加了轮换（因为用户问「怎么只有一个模型」），用户确认后**撤掉**。撤的理由：
同一项目里调研/架构/审查各用不同模型 → 出问题不好归因、成本忽高忽低、学习器样本变少收敛更慢。

**正确做法**：想让用户"看见"配了哪些模型，靠**用量页列出全部**（含"未使用"/"配额耗尽"），
而不是靠轮换制造使用。

保留的：删掉死函数 `pick_agent`（72 行零调用）；单日 500 条截断是真 bug，已修。

## 六、其他修复

- **单日 500 条截断**：`_daily` 原是 `[-500:]` 定长窗口，一天分派超 500 次，
  当天更早的行被挤掉、当天的量少算。改成**按天保留**。
  ⚠️ `record()` 里三步顺序不能换：**先折叠 → 再剪枝 → 最后写盘**（写反会把没归位的行删掉）。
- **`set_budget` 补锁**：它由 Flask 线程调用、`record` 在调度线程，两者都在"读 `_daily` 重写整份文件"。
- **学习器空模型脏样本**：任务取消/分解时 `disp_result` 是 None → model 取到空串 →
  键退化成 `type::`，积出一条"0 成功 15 失败"。修法：model 为空直接丢弃。
- **`project_name` 永远为空**：调用方只传 id。已按 id 载入项目名一起传。

## 七、验过的边界（都验证过"旧代码下会红"）

- 折叠的跨午夜回归（改回"只重算今天" → 5 条红）
- 热力图/趋势的空状态（去掉 `peak===0` 守卫 → 样式里出现 `NaN%`）
- 轮换（撤掉前验证过；撤掉后那几条测试一并删除）
- 单日 800 条不少算（改回 `[-500:]` → 1 条红）
- 观察者记账**真机实测**：聊一句后账上确实多出 `level=observer` 一条（1142 tokens）

## 八、明确不做

- 不引入任何默认费率（`0.50`/`0.30`/`0.15`/「混合均价」全是这个 bug 本身）
- 不把 `_guess_cost()` 的档位换算成钱（同一 bug 换皮）
- 不加输入/输出 token 拆分（`UsageRecord` 只存总量）
- 不做币种/单位配置
- 不做历史趋势图/热力图/连续天数（做了一版，用户看完说"页面东西太多"→ 只留时间段 + 按模型表）

## 九、统计页最终形态

```
[用量]  [累计至今 | 本月 | 本周 | 今日]        [刷新]
统计自 2026-09-11（只保留最近 400 天）

模型                  tokens    占比    单价      费用
deepseek-v4-flash     375.2K    100%    —       未配置价格
deepseek-v4-pro       未使用     —      —        —
glm-5.2   [配额耗尽]   未使用     —      —        —
...
```

日历口径（本周=周一起、本月=1 号起），不是"最近 N 天"的滚动窗口。
配置里的模型**全列出来**（哪怕一次没用过），非 active 的供应商状态直接露出来
—— 注意 `api_store.is_available()` 有"半开"机制，**配额耗尽也返回 True**，
所以报的是 `provider_status` 原文而不是那个会误导的布尔值。
