## ② 病根与统一判据（铺开时唯一要背下来的东西）

**病根一句话**：判据落在"非空/非假"而不是"是不是成功"上，且默认那一侧是好消息；它的**静默孪生**是——失败只 toast 一声，原地渲染成「暂无 X」。GATE3 绿灯、✓阻断、$0.00 是前一种；McpTab 的「失败→没有 MCP 服务器」、Tasks 的「失败→暂无任务」是后一种。

**统一判据** = 样板 README 的两张表（四态判据 + McpTab 字段判据），归纳成四条纪律：

1. **失败是一个答案，不是"没有数据"** —— error 和 empty 是两个相，失败要有自己的文字和重试入口，绝不落进空态文案。
2. **缺失/不认识/矛盾 → 用文字说"不知道"** —— 不许落到好看的默认值（生词回显、「状态未知」、「配置矛盾」同属这条）。
3. **0 只有真数过才许显示**；显示了 0 要解释它意味着什么（计数、金额、工具数同律——money.ts 是这条的正面样板）。
4. **每一态都有文字**，颜色只是辅助（`aria-hidden` 的圆点不算数）。

**载体** = `Async.tsx`（`Loadable` 类型 + `useResource` hook + `AsyncBoundary` 边界）。它的价值在**让调用方没得选**：error 相在类型上就装不下"渲染成空态"这个选项。

### ④0 每一步的通用协议 —— **没浏览器怎么知道没改坏**（先立规矩，再动文件）

1. **一个文件一个提交** —— 坏了单点 revert，不连坐。
2. **四条命令必跑，数字写进 commit message**（在 `frontend/` 下）：
   ```bash
   npx tsc --noEmit                    # 仓库本体（样板期它不含样板目录）
   npx vitest run                      # 仓库默认收集（当前 71 绿，每步往上加）
   # 样板期再加两条（见样板 README §六）：

   npx vitest run --config src/pages/__rewrite_sample__/vitest.sample.config.ts
   ```

4. **每步 ≥1 刀变异自检**：commit message 里写明"把 X 行改成 Y，测试 Z 必须红 + 实测红没红"。样板 README §六那张变异表是格式样板。
