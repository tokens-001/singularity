奇点 —— 一个需求进来之后

你把一句需求丢进去（比如"做一个待办工具，拆成三个文件"），它自己走完下面九步， 产出一个能跑的项目。右边三个东西全程都在后台转。

1

建项目

你写需求、定范围。这一步只登记，不干活。

2

调研

一个模型去查资料、试着写小 demo 验证技术路线。 （今天那个跑到仓库里的 poc/ 就是这步产的）

3

GATE1 —— 等你点头

调研结果给你看，你决定继续还是打回。设成自动模式就跳过。

4

架构（出方案）

几个模型各写一份方案 → 互相挑刺、辩论 → 融合成一份。

5

GATE2 —— 等你点头

融合方案给你看。你点头后，它被拆成一堆子任务。

6

实现（写代码）

每个子任务：开一个独立的 git 副本（叫 worktree，就是沙箱，任务之间互不干扰） → 派一个 agent 进去写 → 跑测试。

7

审查（三关）

机械检查（语法、测试过不过）→ 多模型审查 → 安全审计。 任何一关不过就打回重做。

8

合并

各子任务的产出排队合回主仓库。排队是为了避免两个任务同时改一个文件撞车。

9

GATE3 / 交付

最后点头，打包成品。

全程后台运行

贯穿始终的三样东西

Orchestrator 调度器

主循环。一直在问"下一个该跑谁？跑完了没？" —— 上面九步的推进全靠它。

Tracker 任务表

每个任务的状态存在 .qidian/tasks/ 下的 JSON 文件里。 没有数据库，所以出问题可以直接打开文件看。

模型 API

所有"思考"都调外部模型：DeepSeek / 智谱 / Kimi。
