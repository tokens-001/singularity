## 怎么跑真机（09-17 核过，跑之前照这个来）

- **起后端**：`cd ~/projects/singularity && nohup .venv/bin/python -m singularity.web.app > /tmp/qidian.log 2>&1 &`
- 🔴 **改完代码必须先重启后端再跑真机**（`app.py` 是 `debug=False`，**没有热重载**）。
  判据：`ps -o lstart= -p <pid>` 要**晚于** `git log -1 --format=%ad`。
  09-17 中午实测踩到：跑着的进程是 01:40 起的，而修复是 02:12–02:28 提交的 ——
  **不重启就开跑 = 整轮跑在旧代码上，然后得出"修复没用"的假结论。**
- 🔴 **起后端 = 调度循环也跟着起**（`web/app.py` 启动时那句 `start_loop(concurrent=2)`，
  观察者智能体同理）—— **没有"后端跑着但循环没开"这个状态**。09-19 我据"没监听端口"
  推断"循环没开、不会烧钱"，**是错的**（那次恰好真没在花，因为没有项目可推 —— 结论对、
  理由是编的）。**要判它在不在烧钱，看 `usage_daily.json` 的 mtime 和 `scheduler.log` 有没有 dispatch，
  别看端口。** 停止用 `POST /api/loop/stop`。
  🔵 **并发有两套值**：HTTP `POST /api/loop/start` 默认 **1**（不传 `concurrent` 时）、
  观察者那两条路硬编码 **2**（`_observer_tools.py` 里 `start_loop(concurrent=2)` 那两行）。启动自动起的那次是 **2**。
