# A/B：辩论后「融合」vs「直接取一份」（2026-09-09）

> 那两个数用的基准是 `plans[0]`（链上第一份），而它实际是**最弱**的一份 ——
> 换成「N 份里最好的那份」后，同一批数据变成 **−3.3 ~ −16.5**。

## 问题

架构阶段的 7 波里，融合占 2 波（stage1 五维分析 + stage2 定稿），约 30% 时间。
融合到底有没有增值？如果没有，可以砍掉省 2 波。

## 方法

`tests/integration/ab_fusion.py`：同一个 brief 跑一次真实委员会，截获辩论后的 N 份方案，然后

- **A = `fuse_architecture(方案们)`**（现状）
- **B = 方案[0]**（跳过融合）

两臂共用同一次委员会运行，差异只在最后一步 —— 隔离「融合」这一变量。
盲评用委员会之外的模型，甲/乙 顺序互换各评一次取平均（抵消位置偏好），5 维度各 0-10 分。

## 结果 ①：2 模型阵容（deepseek-v4-flash + deepseek-v4-pro）

盲评模型 `glm-5.2`，3 组：

| brief | A 融合 | B 单份 | 差 |
|---|---|---|---|
| 1 任务队列 | 38.0 | 40.0 | −2.0 |
| 2 文件同步 | 20.5 | 19.5 | +1.0 |
| 3 多租户计费 | 28.5 | 29.0 | −0.5 |
| **均值** | **29.0** | **29.5** | **−0.5** |

A 胜 1/3。**没有证据表明融合增值**，但样本 3 组、差异在噪声内。

不砍的理由：B = `plans[0]` 意味着链上第一个模型永远胜出，砍融合等于引入新偏差；
且两成员同源（flash+pro），方案高度相似，融合本来就没多少可合的。

## 结果 ②：3 家异源阵容 —— 融合明显增值

### 2a. 首次尝试（pro + glm-5.3 + kimi-k3）失败

brief 1 只有 1 个模型产出，另外 2 家静默失败，实验中止。
疑似慢/思考模型撞 240s 单次调用超时（kimi-k3 是 `slow`；glm-5.3 实测返回 `reasoning_content`，
但 `models.toml` 标 `reasoning=false`，标注错误）。换成快速阵容后三家均正常出稿。

### 2c. 快速阵容 + **开辩论**（`AB_NO_DEBATE=0`）

### 三轮对比

| 阵容 / 设计 | 组数 | 均值差 | A 胜率 |
|---|---|---|---|
| 2 模型**同源** + 辩论 | 3 | −0.5 | 1/3 |
| 3 家**异源** + 无辩论 | 3 | +7.8 | 3/3 |
| 3 家**异源** + 辩论 | 2 | **+11.0** | 2/2 |

**方向坐实**：融合的价值取决于输入方案的多样性（同源 −0.5 vs 异源 +7.8~+11.0，差一个数量级）。
辩论**没有**削弱融合价值，反而更高 —— 可能因为辩论让三份方案各自演化得更不同。

### ⚠️ 数值不可信（两个系统性偏向）

1. **评分维度全是"覆盖度"**（模块/数据/API/任务/风险）—— 融合的机械作用就是取并集，
   这个评分表**天然奖励融合**。
2. **B = `plans[0]`（链上第一个模型），不是最强的那份** —— 若第一份偏弱，融合优势被放大。
   **公平对照应是「融合 vs N 份里最好的那份」**。

反证：brief 2 的融合稿 9483 字，比任何单份都短（单稿 13114/14433/11873）却高 6.5 分 →
说明不全是"越长越全越高分"，偏向存在但不是全部。

# 2026-09-10 复核：上一页的结论被推翻

## 1. 基准错了：`plans[0]` 是最弱的那份

原实验 B = `plans[0]`。用「N 份里最好的那份」当基准重算（`ab_best_baseline.py`）：

| 缓存（阵容） | 融合 − 最好单稿 | 胜率 |
|---|---|---|
| `.ab_cache_2models`（flash+pro +辩论） | +3.3 | 2/3 |
| `.ab_cache_3v_nodebate`（三家，无辩论） | **−3.3** | 1/3 |
| `.ab_cache`（三家 + 辩论） | **−16.5** | 0/2 |

明细最能说明问题 —— `第一份` 总是远低于 `最好单稿`：

```
.ab_cache  brief1: 融合 27  最好单稿 44  第一份 28
           brief2: 融合 29  最好单稿 45  第一份 30
```

所以原「+7.8 / +11.0」是**拿最弱那份当基准撑出来的**。

## 2. 关掉截断，符号又翻转 —— 测量本身不稳

脚本为防 prompt 过长把每份截到 10000 字。融合稿天然更长，**被砍得最狠**：

```
.ab_cache brief1: 单稿 8815/5218/8384 字（都没到 10000，未截断）
                  融合 16200 字 → 被砍掉 38%
```

`AB_MAX_CHARS=0` 关掉截断重跑：

| 缓存 | 截断 10000 | 不截断 |
|---|---|---|
| `.ab_cache`（三家+辩论） | −16.5 | **+5.5** |
| `.ab_cache_3v_nodebate` | −3.3 | −9.7 |

**同一个缓存、同一份稿子，只因为让不让评委看全，从 −16.5 变 +5.5。**

## 3. 还发现融合阶段自己就把方案砍了

`fuse_architecture` 里 `o[:2000]` —— 方案实际 8k~20k 字，**裁判和定稿人只看得到前 ~15%**。
已于 801f527 修复（可配 `QIDIAN_FUSION_PLAN_CHARS`，默认 20000）。

## 4. 测量缺陷清单（本轮全部踩过）

| 缺陷 | 后果 |
|---|---|
| 基准取 `plans[0]` | 结论完全反向 |
| 输入截断对长稿不利 | 符号翻转 |
| rubric 全是覆盖度 | 变成测篇幅，不是测质量 |
| 模型署名丢失（截获的是纯文本） | 事后无法归因"哪家碾压" |
| 评委可能弱于选手 | 分数不可信 |
| 单次生成方差极大（同模型两次相似度 0.03~0.17） | 单题样本无意义 |
| 模型 id 是浮动别名，无法 pin | 结论不可复现 |
| 思考模型当评委烧光 max_tokens | content 空，打分失败 |

## 5. 已加的判据工具

- `tests/integration/pairwise.py` —— 成对比较 → Bradley-Terry + bootstrap 置信区间。
  **CI 重叠 = 评委分不开这两个方案**，把"评委天花板"变成可观测信号。
- `tests/integration/ab_rank.py` —— 让评委**排序**而非打分，一次调用得到完整顺序，
  分解成 6 条成对胜负，比逐对调用省 12 倍。
- `tests/integration/ab_debate_vs_ref.py` —— 走真实生产路径跑委员会，
  读 `.qidian/.last_fusion.json` 拿**署名**，对照外部参照模型。
