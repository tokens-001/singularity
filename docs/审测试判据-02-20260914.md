## 2. 🔴🔴 最大的那条**不在"假绿"里**：循环导入让一份测试**单独跑必红**

> 是 agent 3 在顺手跑变异时撞出来的，**我复核属实** —— 而且它比前面两条严重得多。

- **症状**：`pytest tests/test_scheduler/test_thinking_params.py` **单独跑 = 1 failed**
  （`_api_admin.agent_update` 撞 `AttributeError: module 'dispatcher' has no attribute 'update_agent'`），
  **在整套里却是绿的** ⇒ **顺序依赖**。
- **根因**：`dispatcher.py` 末尾三句 `from ..._dispatch_* import *`（把三兄弟再导出），
  而**三兄弟各有一条** `from singularity.scheduler.dispatcher import (...)` ⇒ **一个毂 + 三根双向辐条**。
  **谁先被导入谁吃亏**：先导 `_dispatch_crud` 时它第 1 行去导 `dispatcher`，
  `dispatcher` 跑到底部执行 `from ..._dispatch_crud import *` —— 而那一刻
  `_dispatch_crud` **刚执行到第 1 行**、`update_agent` 还没定义 ⇒ `dispatcher.update_agent` 干脆不存在。
- **实测三方向**（`python -c` 逐个验）：
  ```
  先导 dispatcher       → hasattr(update_agent) = True
  先导 _dispatch_crud   → hasattr(update_agent) = False    ← 洞
  ```
- **修法**：把 `dispatcher` 那三句星号导出改成 **PEP 562 惰性转发**（`__getattr__`）。
  谁先被导入都行 —— 三兄弟要的名字定义在 dispatcher **前面**（导入时就有），
  外面要的名字**等访问时再解析**（那时三兄弟早加载完了）。
  ⚠️ 全仓**无人**用 `from dispatcher import *`（扫过），所以不需要保留"再导出"语义。
  ⚠️ **模块级 `__getattr__` 管不到函数体内的全局名查找** —— `dispatcher` 自己有一处
  用 `_dispatch_crud._load_custom_agents`（两个调用点），补了个显式的惰性访问 `_custom_agents()`。
- ✅ **顺带解决的**：OPEN.md 里登记了很久的
  「`import singularity.scheduler._dispatch_exec` 单独导入会炸 —— **登记着，不做**」
  —— **同一个根，一起好了**（现在四个导入方向全通）。
- ⚠️ **试过、不行的两条**（免得再试）：① 把辐条那条反向 import 挪到**文件末尾** ——
  报错只是挪到隔壁 `_dispatch_skills`；② **辐条侧**惰性化 —— 不行，
  `_dispatch_skills` 会给 `_MCP_CACHE` **赋值**（带 `global`），惰性化会让它变成遮蔽。

### 6.1 🔴 **新发现（生产行为，不是测试问题）** —— 这条比假绿重要

`neijinglu._is_redundant_failure` 的两道 pass 守卫**认不出真机的形状**。

**真机证据**（直接读 `.qidian/traces/*.json`，不是推的）：

```
{'verdict': '通过', 'action': 'pass', ...}    ← 成功的任务
{'verdict': '阻断', 'action': 'abort', ...}   ← 被拦的
```

而守卫是 `if action == "pass" and not verdict:`（verdict 是"通过"、真值 ⇒ 不触发）
和 `if verdict == "pass":`（"通过" ≠ "pass" ⇒ 不触发）⇒ **通过的 trace 不被豁免**。
调用方 `_save_trace` 拿这个判据做**存储裁剪**（截断 `agent_output` / `changed_files`）
⇒ **成功任务连续几条之后 trace 被系统性截断**，而 docstring 写的是"只对 **非 pass**
的 trace 做去重"——**行为与声明相反**。

**变异实测坐实了两条假绿**：`test_pass_action_no_redundant` /
`test_pass_verdict_no_redundant` 里写进去的 trace 用的是**默认签名**（`阻断`/`abort`），
跟当前那条**对不上** ⇒ `match_count` 恒 0 ⇒ **删掉那道守卫照样绿**。
⚠️ 我试着把它们改成"同签名" —— **该用例当场变红**，等于用实验证明了
"代码没做它声称的事"。**改动已还原**（改守卫 = 改生产行为，等用户拍）。
