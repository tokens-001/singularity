```
────────────────────────────────────────
**背景**：今天同一个病换了五次字符串，**五次都是碰巧撞见的、不是搜出来的**：
  1. 取消标记：`cancelled_by_user` vs `cancelled_during_pause`
  2. 升级：`escalation_exhausted` vs `no_escalation_path`
  3. MCP：`add` 那一半 vs `delete` 那一半
  4. 同样的命令包装：类方法 `_run_command` vs 模块级 `_run_command`
  5. 敏感文件黑名单：web 那张 vs agent 那张

每一次都是「**同一件事写了两遍，改的时候只改了一遍**」——
于是要么新的一半不生效（功能静默死掉），要么旧的一半还开着（修复漏了一个出口）。

────────────────────────────────────────
【要你找的**形状**】（**只找这个形状，别顺手"扫 bug"** —— 那是另一个窗口的活）

  同一个**判断 / 词表 / 名单 / 默认值 / 计数口径 / 状态集合**在**多个地方**存在，
  而且**几处之间已经不一致**。

典型信号（拿来当搜索起点）：
  · 同一个字符串常量在两处各自定义（或一处是字面量、一处是常量）
  · 两个函数体长得几乎一样，只差一两个分支
  · 两张"该一样"的表，条目数不同
  · 同一条路有两个入口，只改了其中一个
  · "终态集合 / 早退集合 / 白名单"在多处各写了一遍

**优先扫这两个已知雷区**（今天五次里有四次出在这儿）：
  ① **门禁 / 权限判定**  ② **状态机与终态集合**

────────────────────────────────────────
【产出】每一对给五项：
    · 两边各在哪（**符号名，别写行号**）
    · 两边现在各是什么
    · **哪边是现役**（谁真的在被调用）
    · 不一致会造成什么后果（哪一侧是"洞"、哪一侧是"死功能"）
    · 你怎么确认的（追到调用层了吗）

⚠️ **别列"疑似"当战果** —— 只报你**追到调用层确认过**的；
  确认不了的单独放一节，标题写「候选：没追到调用层」。
⚠️ **别给修法**（修法我自己定，你给修法我反而要花时间核你的修法）。
⚠️ 篇幅不限，但**每一对都要能落地**：我拿着你的符号名应该能直接找到那两处。
```
