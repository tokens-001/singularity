# 角色体系重构记录（16 → 3）

> 2026-09-07，commit e90aec7。记录「16 角色砍到 3 个」的实验依据和最终架构。
> 本文是「角色」这一块的最新权威说明，替代 `现状速写.md` / `现状结构图.md` 里「16 角色」的旧描述。

## 一句话结论

16 角色里只有 5 个真在干活（注入 system_prompt），其余 11 个空转。三个 prompt 层实验验证后，砍到 3 个真角色 + 4 个独立引擎。**多视角碰撞是唯一证实的核心价值。**

## 三个实验（prompt 层，deepseek-v4-pro，单次采样）

| 实验 | 结论 |
|------|------|
| 角色约束（裸 vs backend_engineer vs implementer） | 有增量但小：防御细节/测试完备性的锦上添花，非质量跃升 |
| 多视角（委员会 vs 同档单模型，挤掉 Schema 水分） | **真比单模型强**：补盲区、抓矛盾、多洞察（URL Safety / 预生成码池 / 301 缓存风险） |
| debugger / builder（vs implementer 打回 / 直写） | debugger 无增量；builder 价值在「@files 输出规范」治 thinking 模型污染，非「拆解」 |

## 最终架构

| 层 | 承担者 | 说明 |
|------|------|------|
| 实现 | `implementer`（roles.toml） | 唯一实现角色 |
| 验收 | `qa_engineer`（roles.toml） | 新接线：约束验收，补 multi_model_review 不查的「约束」维度 |
| 安全审计 | `security_auditor`（roles.toml） | 新接线：LLM 五维审计，补正则抓不到的设计层漏洞 |
| 架构 | fuse 委员会（execution_judge） | builder/skeptic/analyst 三视角，独立于 roles.toml |
| 调研 | observer 链路 | 独立角色体系（product-manager / … / researcher） |
| 机械质检 | supervisor.py | 独立引擎 |

## 砍掉的 13 个角色

- **5 工程师**（frontend/backend/data/ai/devops_engineer）：system_prompt 几乎一样，只在 LAYER_ROLE_MAP 路由到，增量价值小
- **debugger**：修 bug = implementer 打回重试，无增量
- **builder**：「拆解」价值存疑，输出规范已下沉全局
- **researcher / supervisor / reviewer / system_architect**：职能由 observer / supervisor.py / validator / fuse 独立引擎扛，system_prompt 定义是死代码
- **ai_architect / frontend_architect**：架构细分视角从未实现，实验 2 证明通用三视角够了

## 下沉的约束（进 `_exec.py` 全局底线）

- 错误处理：输入为空、异常输入、边界情况都要处理
- 输出规范：多文件改动，每个文件一个代码块，开头 `@files` 注明路径
