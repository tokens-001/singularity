## 三、失败原因

**先说结论**：**不是"模型不会写 Go"，是预算在"排队"和"打转"两处被吃光，没轮到"写代码"。**

**⓪ 根因（09-27 03:2x 翻 `T1` 现场翻出来的）：架构自己跟自己打架 —— 要 Go，验收判据却是 pytest。**

`T0`（= 运行时那个 `T1` 骨架）**同一个任务对象内部**就矛盾：

```json
"description": "创建 Go module、internal/types/contracts.go …… **建 tests/conftest.py**、Makefile、**tests/test_build.py** skeleton"
"acceptance": {"check": {"argv": ["python3","-m","pytest","-q","tests/test_build.py","-k","skeleton"]}}
"estimated_files": ["go.mod","internal/types/contracts.go","tests/conftest.py","tests/test_build.py","Makefile"]
```

**全局范围**：`tech_stack.language` = 「**Go 1.22+**：CGO_ENABLED=0…」，
而 **16 条约束的 `check.argv` —— 16/16 全是 `python3 -m pytest`**；
测试任务 `T6`–`T12` 全是 **`tests/*.py`**；`T11` 甚至是「`tests/test_module_boundaries.py`
**解析 Go import 图**」（用 Python 测 Go）。

⇒ **模型没法同时满足**（写 Go 则 pytest 测不了；写 .py 则违背 tech_stack）
⇒ **这就是那 811 秒**：275,806 token · 6 个工具轮 · **0 个文件改动** · **正文 0 字**
（执行器自己的判词：「单次调用撞上限被掐断，正文零产出（工具轮 6 次，改动 0 个文件）」，
唯一看到的工具结果是一个 `ls`，列出来**是空目录**）。

**成因**：历轮**全是 Python**（`pyproject.toml` / `jsonstat/` / `logstat/parser.py`），
模板与惯例都是 `.py`。这轮架构**换了实现语言（Go），没换测试脚手架**。

🔴 **为什么没被拦住**：`_validate_architecture` / `classify_arch_issues` 的注释写着设计意图 ——
「分两档……**非致命（只记）**：`data_model` / `tech_stack` / `constraints` 等」。
那个理由**是对的**（不该因为缺 `data_model` 就把好活挡在门外），
**但它拦的是"字段缺不缺"，没拦"字段之间打不打架"** ——
这轮两个字段**都在、都非空，只是说的不是一种语言**。

✅ **09-27 已修**：新增 `_arch_language_conflict`（`_workflow_phases.py`），
把它归**致命档**（`classify_arch_issues`）⇒ **GATE2 会拦住**。

**② 两个失败任务的死因【完全不同】—— 这是本节最重的读数。**

`dispatches` 的语义（`_exec.py` 写入处 + 那段读法注释）：`{"at","elapsed","turn","attempt"}`，
`at` = **这次 dispatch 结束的时刻**，`elapsed` = 它跑了多久 ⇒ **起点 = `at − elapsed`**；
**`max(attempt)+1` = 这任务被整个重跑了几次**。

| | `T1` 骨架 | `T3` filter |
|---|---|---|
| 总寿命 | **811s** | **951s** |
| **排队** | **2s（0%）** | **813s（85%）** |
| **在跑** | **802.3s（99%）** | 137.0s |
| dispatch 次数 | **5 次** | 1 次 |
| `max(attempt)+1` | **3 次**（被整个重跑 3 遍） | 1 次 |
| 每次耗时 | 200.8 / 127.4 / 164.3 / 196.1 / 113.7 | 137.0 |
| 产出 | **零文件** | **零文件** |

T1 那 5 次 dispatch **首尾相接、中间没有缝**（01:54:30 起 → 02:07:59 终，`at` 连着排）。
⇒ **它一秒都没排过队，811 秒全在跑 —— 跑了 3 遍，一遍也没写出东西。**

⇒ **结论要改**：
- **`T1`（骨架，也就是杀死整轮的那个）不是被排队拖死的，是纯打转。** 它不缺时间。
- **`T3`（filter）主要是排队** —— 排 813s，上场只剩 137s。
- **`T5`/`T9` 连 `partial_usage` 都没有** ⇒ **一次都没进 dispatch**，整轮在排队（连 T3 都不如）。

**③ 那个 `cap=112s` 是 T1 自己吃出来的，不是排队。**

```

stream_over_budget:112s:cap=112s:chars=0:loops=9680:idle=0s
```

⇒ 那一刻剩余预算 ≈ 204s，跑掉 ~90s 后 `cap` 落到 **112s** —— **对得上**。
⇒ **112s 是"它自己重跑 3 遍"吃剩的，不是"在队列里等掉的"。**
