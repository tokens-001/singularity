### 1. `_is_gate_reply`（第三批 ①）——有新误判面，先结论后取值

**结论：改出新问题。** 要修的三个旧坑是真修好了（sanity 实测全对），但新规则③和短词新判据各开了一面新的误判：

  - `特别棒，确认通过` / `效果特别好，确认` → **rejected**（旧版 approved；"别"在"确认"前）

- "`validation.confidence = quality.get('confidence', 0.5)` 覆写 validate 的真分"——`validate()` 全函数（`validator.py:38-89`）**没有任何一处给 `report.confidence` 赋值**，所有 return 路径都带着 dataclass 默认值 **0.0**（`validator.py:33`）。没有真分可盖。
- 0.5 这个默认值正常路径**取不到**：`post_execution_hook` 两个 return 都必带 confidence（异常早退 `validator.py:126`、正常出口 `:141` 是现算的）。`_exec.py:656` 实际是把 hook 现算的分接进 validation 的**正常通道**，不是覆写。
- "hook 抛异常时兜的还是 0.5"——字面半真（except 里 quality 确实带 0.5，`_exec.py:664-666`），但 `validation.confidence = ...` 的赋值在 **try 块内**（:656），异常路径根本没执行；confidence 停在 0.0，随后 `:685` 的 `min(0.0, 0.5)=0.0`。0.5 只会流到反馈**文本**（`:398-399` 的"置信度: 0.50"字样），进不了决策。
- 因此"真分 0.2 被改成 0.5、立即升级错成同模型重试"的链条不存在：0.2 会原样经 :656 落进 validation，`_decide_cascade` 里 `conf<0.35 → break 升级`（`_exec.py:392-393`）照走。

**H 不成立。**

- "直接删掉 :656 会把 run_post_exec_checks 的惩罚传丢"——惩罚进决策的桥是 **`:685-686` 的 min**（读的是 `quality["confidence"]`，`_review.py:231` 等处施的罚都落在这个 dict 上），不经过 :656（:656 在审查**之前**执行）。删掉 :656，min 照样把罚传到位——传丢的不是惩罚。
- 删 ：656 的真实坏法是**反方向**：validation.confidence 恒 0.0（validate 不产分）→ retry 态任务全部 `conf<0.35` 立即升级，"该同模型重试的"全被升级烧钱——**不是** `:681-683` 注释里那个"惩罚传不到→烂活被 cascade_accept 放行"的老病（那个病反而更不可能复发）。
- "正解是保住 validate 原分、min 对原分做"——**无原分可保**（validate 恒 0.0）。H 与 D 共享同一个错误前提。
- 说句公道话：H"别直接删"的**结论方向**歪打正着（直接删确实会坏），但坏的机制与它说的相反；这一行真正值得改的只有一处——hook 异常分支 quality 里的 `"confidence": 0.5`（:666）是编造数据，但它只污染反馈文本，不动它也不影响决策。
