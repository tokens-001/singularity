**不是一个病，是同一个治疗点多处漏。**

治疗点就一句：**把"这次是被我们断的"这个事实，从 `_stream_call` 一路贯通到判据。**

现在这个事实的处境：
- **产生**在 `openai_agent._stream_call`（`_over_budget`）✅

所以"还有多少"是**可数的**：**实** 19 条 · **面** 2 条 · **疑** 6 条，
且它们**几乎全部**是上面那一个治疗点的分支。

### 五之二、2026-09-19 核到底的三条（疑1 / 疑6，+ 结论更正）

**疑6 —— 原文框错了，真缺口在写侧（已修）**

原文说「只认『降级运行』一个子串 ⇒ 别的失败原因不会被标出来」。**这不成立**：那条判据
**就是**只为「上游失败、这任务降级起跑」这一种处境立的，写侧全仓只有一句
（`tracker.ready_tasks`），读侧认那一句是对的 —— 换个措辞去认才是开集枚举那个坑。

**真缺口是另一回事，而且更硬**：写侧那句 `task.error` **只在 `BLOCKED→ROUTED` 那一支写盘**。
其它状态（PENDING / ROUTED 起步 —— 上游早就失败、返工循环把任务重排回来）只改**内存**，
而这条路下游紧接着就是 `cas()` / `transition()` 派发，那两步都是「重读盘上那份再覆盖写」
⇒ 内存里设的 error **当场丢掉**。读侧走的是 `read_task()`（从盘上读）⇒ **对这类任务，
那条人审提示一次都不会出现**（2026-09-13 真机那条能看见，是因为那个任务**先 BLOCKED 过**）。

✅ **已修**：改成「状态是 BLOCKED **或** 盘上那句和将要写的不一样」就 `_write`。
测试 `tests/test_scheduler/test_degraded_mark_persisted.py` 从**写侧真实入口**（`ready_tasks()`）
走一遍再断言盘上 / 读侧认不认 —— 变异（去掉写盘那一支）两条全红。
现存那两条老测试**自己把措辞塞进 `transition(error=...)`**，所以它们钉的是「读侧认得这个子串」，
**写侧改词一个字都不会红**（同「测了函数没测接线」那个形状）。

**疑1 —— 核到底：不是"传错根"，是"那时候根本没有根"**

原文（和 09-19 复核）写的是「产物在 worktree 而传了项目仓根」。**读全之后是更坏的形状**：

`_exec.run()` 的 turn 循环 `finally: _cleanup_wt(wt)` —— **worktree 在 `run()` 返回前就已经
被删掉了**（`cleanup()` 是 `git worktree remove --force` + rmtree，见 `_git_worktree.cleanup`）。
而 `_task_runner.finalize` 的兜底 QA（`if not qa_verdict and not cancelled`）是在那**之后**
才跑的 ⇒ 那些 `changed_files` **在盘上任何地方都不存在**（只在 `refs/qidian/pending/<id>` 里）。

⇒ 这条兜底路上，`_check_artifact` 能做的事**只有**：
· `py_compile` 静默跳过（文件不在 root 下）；
· `ruff` 走 `evidence["lint"] = "no changed py file under root, skipped"`；
· 测试跑的是 **项目仓 HEAD 的**测试套件（改动还没合并）——**与这个任务的产出无关**；
· `_all_empty`（2026-09-15「交付物被自己清空」那个守卫）在这条路上**恒返回 []**，等于不设防。

**⇒ 修不了"传对根"**：没有正确的根可传。要动就得先定**没有盘上产物时该说什么**
（是"未检查"还是"没法查"，以及要不要出声）—— 那是决定，不是 bug 修。**未动，等拍板。**
🔵 影响面：只在这条兜底路上（有 merge_request 的任务在 worker 里已经查过了），
所以**不会误放一个本该拦的合并** —— 它误的是"我查过了"这句话本身。

🔵 **A5 和 C4 是同一个形状**：新的 `"deadline"` / `"timeout"` 已经在写，但**枚举注释没同步、下游也没有专认 `"timeout"` 的分支**。
