# 观察者智能体 — 需求文档

## 背景

奇点目前是一个多模型任务编排系统，用户可以提交编码任务，系统通过 E/E+/D 三层模型委员会执行、验证、合成。

当前问题：
1. **交互口太多**：SSE 事件推送、任务轮询、心跳面板、成本/质量趋势各自独立，用户要切换多个面板
2. **被动查询**：用户必须手动刷新或等待 SSE 推送，无法主动问"为什么 D 层选了 Opus？""任务 123 卡在哪？"
3. **没有统一交互层**：缺少一个能理解用户意图、主动汇报、被动回答的智能体

## 目标

打造一个**观察者智能体（Observer Agent）**，嵌入奇点调度器进程，作为平台与用户的统一交互点。

## 功能需求

### F1: 系统状态查询
用户可以用自然语言询问系统状态，智能体实时回答：
- "现在有几个任务在跑？"
- "今天用了多少 token？花了多少钱？"
- "最近有失败的任务吗？原因是什么？"
- "D 层的平均耗时多少？"

### F2: 任务级问答
用户可以对具体任务提问：
- "任务 abc123 为什么失败了？"
- "任务 def456 的 judge 评分是多少？"
- "任务 ghi789 经过了哪几层？被哪个模型执行的？"

### F3: 异常主动推送
智能体自动检测异常并主动告知用户：
- 任务停滞超过 N 分钟 → 推送告警
- Judge 检测到模型偏差（某个模型 pass rate 异常高/低）→ 推送告警
- 成本异常（单日消耗超过阈值）→ 推送告警
- Worktree 泄漏或心跳文件积压 → 推送告警

### F4: 操作建议
智能体可以给出操作建议，用户确认后执行：
- "建议释放被 held 的任务 abc123，原因：依赖已满足超过 10 分钟"
- "建议重试任务 def456，失败原因是网络超时，非逻辑错误"
- 用户回复"执行"→ 智能体调用对应 API

### F5: 编码辅助
沿用当前 agent 形态（E 层执行），不改变。观察者智能体只负责交互和监控，不参与编码执行。

## 非功能需求

### NF1: 不侵入执行路径
观察者智能体是旁路系统，不修改 scheduler/dispatcher/executor 的任何执行逻辑。挂掉不影响任务执行。

### NF2: 同进程运行
不单独部署。随 Flask 进程启动/停止。使用内部 Python 模块直接访问 witness/tracker/judge 数据，不走 HTTP API。

### NF3: 双向通信
- 使用已有 WebSocket（bridge.py，端口 5051）作为通信通道
- 前端通过 WebSocket 发送用户消息，智能体通过 WebSocket 返回回答
- 保留 SSE（/api/events）用于已有的仪表盘事件推送，不破坏现有功能

### NF4: 零新依赖
不引入新的 Python 包或前端框架。复用已有的：
- `websockets` 库（bridge.py 已用）
- `OpenAIAgentExecutor`（已有 tool-use 能力）
- 前端原生 JS（fetch + WebSocket + DOM）

### NF5: 渐进替换
现有仪表盘面板逐步退场（不强制），用户可以选择通过聊天交互或保留原有面板。
