# Ponytail 懒惰检查

写任何代码前，按以下顺序逐级判定。当前级满足即停止，不往下走。

## 六级懒惰阶梯

1. **这个功能真的需要吗？** → 不需要就跳过（YAGNI）。需求本身可能过度。
2. **标准库有吗？** → 用 stdlib。Python 的 `pathlib`/`json`/`re`，JS 的 `URL`/`fetch`。
3. **系统原生支持吗？** → 浏览器原生 `<input type="date">`，OS 自带工具。
4. **已安装的依赖里有吗？** → `pip list`/`npm ls` 查已有包，不新增依赖。
5. **一行能写完吗？** → `sorted(data, key=lambda x: x.age)`。一行搞定不用三行。
6. **否则才写最小实现** → 只写真正需要的代码。不留扩展点、不预设计。

## 输出规则

- 每次跳过写代码时，加注释说明用了哪一级，以及如果以后要升级应该去哪：
  `<!-- ponytail: browser has one → if range needed, use flatpickr -->`
- 评估标准：删掉任何一行会破坏功能吗？不会 → 删掉。
- 安全/数据完整性/可访问性相关的必要代码不缩减。

## 反模式（识别并拒绝）

- "万一以后需要呢" → 以后再加，现在不写
- "加个抽象层更灵活" → 还没用到第二个实现就别抽
- "这个工具函数以后能复用" → 真正复用两次以上再抽
