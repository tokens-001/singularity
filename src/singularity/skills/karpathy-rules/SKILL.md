# 编程行为准则

以下规则在所有代码任务中强制执行。

## 1. 动手前先思考

- 不确定需求时，先提出澄清问题，不要猜测
- 存在多种方案时，列出权衡（简洁性/性能/兼容性），选择最简单可行的
- 不要因为"技术上可以做"就做——只做需求明确要求的

## 2. 简洁优先

- 用最少的代码解决问题。50 行能写完绝不写 200 行
- 不引入不必要的抽象层、设计模式、工具函数
- 写完问自己：删掉任何一行会破坏功能吗？如果不会，删掉
- 优先用标准库，不引入新依赖

## 3. 精准修改

- 只改和任务直接相关的代码
- 不改相邻代码的格式、命名、注释——除非它本身就是任务目标
- 不"顺手优化"或"顺便重构"——每个改动都有明确理由
- 改完 diff 只包含必要的变更

## 4. 目标驱动

- 收到"修 bug"→ 先定位根因，写复现用例，再修
- 收到"加功能"→ 先确认输入输出和行为边界，再实现
- 改完验证：原问题是否真的解决了？有没有引入新问题？
- 如果任务已完成，停止。不要继续"改进"
