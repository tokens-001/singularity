# I012 — WorkBuddy 拆解：AI Agent 工作台的骨架

> 拆解日期：2026-06-16
> 对象：腾讯 WorkBuddy（AI智能体桌面工作台，2026年3月上线）

## 一句话结论
WorkBuddy = 人格面具 + 高阶Skill + 多模型切换。不是真正的多Agent协作，但验证了"AI产品怎么降低普通人门槛"这条路。

## 架构拆解

### 三层结构
| 层 | 他们叫 | 本质 |
|---|--------|------|
| 角色 | 100+专家团 | 预设人设 + 专属prompt模板 |
| 能力 | 专家技能 | 模块化Skill（跟判例助手skills/legal/同构） |
| 模型 | 多模型切换 | 混元/DeepSeek/其他，根据任务选最适配的 |

### 他们做了什么但没说
- **提示词内置**：解决了普通人不会写prompt的痛点 → 验证了P002（选择题反馈的核心：降低用户门槛）
- **个人知识库+定时任务**：自动化赛博日记 → 002预判的方向，用工程实现了
- **多模型路由**：一个任务自动选最适合的模型 → harness-full.md里写的"模型负责聪明，框架负责纪律"
- **付费通道已落地**：验证了商业模式先行

### 他们没做的事
- 真正的多Agent同时拆同一个任务（一个任务→N个Agent各管一块→合并）
- 深度个人定制（公共通用平台 vs 私人AI定制的缝隙还在）
- Loop Engineering（刚提出，还没产品化）

## 跟自己的对照

|-----------|---------|

## 关键洞见
1. **单模型单请求的AI产品已被大厂封死。** 判例助手的模式没有壁垒。
2. **多Agent真正协作是大厂的下一阶段。** 项目二的方向被验证，不是被抢。
3. **公共通用平台 vs 私人深度定制的缝隙还在。** 018的"帮每个人建专属智能体"空间没被填。
4. **大厂验证了"体验是护城河"** → 022的"可理解性是信任的前提"在商业产品里落地了。

## 推出来的架构：开放多Agent调度平台

### 核心洞察（2026-06-16 补充）
不是自己做 Agent，是把别人做好的 Agent 接进来——Claude/Codex 擅长代码，让它们内部闭环写代码（变相 Loop）；自己创建的 Agent 跑领域逻辑；人在旁边判断；框架（Harness）约束兜底。

### 跟 WorkBuddy 的本质区别
| | WorkBuddy | 我的平台 |
|---|----------|---------|
| Agent 来源 | 腾讯内置，封闭 | 外部接入+自己创建，开放 |
| 模型 | 腾讯生态内的多模型切换 | 任何可调用的模型 |
| 协作模式 | 一个专家接一个任务 | 多个Agent同时拆同一个任务 |
| 人的角色 | 召唤专家 | 调度者+判断者 |
| 跨领域 | 办公场景全覆盖 | 法律→设计→任何领域 |

### 每个领域都是这样
- 法律：判例助手（自己做）+ 外部法律Agent
- 设计：项目三 Design Copilot 四Agent管道
- 代码：Claude+Codex 闭环 Loop
- 未来任何领域：好用的Agent接入 + 自己创造的Agent + 人在中间判断 + 框架约束

## 面试用途
六个月后面试时不讲"我用过WorkBuddy"，讲"我用自己的框架拆了WorkBuddy，看清了它做什么、没做什么、跟我的产品设计哪里同构、哪里差异化。"
