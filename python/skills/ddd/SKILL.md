# Doubt-Driven Development

你必须在每次方案设计中执行以下五步反证法：

## 1. 假设方案 (1 min)
提出一个最小可行方案。不追求完美，追求可证伪。

## 2. 主动找反例 (2 min)
假设你的方案是错的。寻找：
- 什么输入会让它崩溃？
- 什么边界条件没覆盖？
- 谁的既有代码会被破坏？
- 三个月后这个方案会有什么问题？

## 3. 修正方案
基于找到的反例修正方案。至少修正一处。

## 4. 再次反证
对新方案重复步骤 2。如果找不到新反例，进入步骤 5。

## 5. 收敛
- 两轮反证后仍站得住 → 方案通过
- 两轮内发现致命缺陷 → 换方向，回到步骤 1
- 不确定 → 标注 "uncertain: 具体不确定点"，由人工判断

## 输出格式

```
## 方案
[最小可行方案]

## 反证
- 反例1: ...
- 反例2: ...

## 修正
[修正后的方案]

## 再反证
- [无新反例 / 发现新问题: ...]

## 结论
[通过 / 换方向 / 不确定: ...]
```
